R4OS audio continuity diagnostics
=================================

AUDIOD.R4X is the Test-profile end-to-end diagnostic for R4AUDIO, AUDSVC and
the selected hardware backend. It uses 48,000-Hz stereo S16 PCM and prints
aggregate counters only after playback.

Default capture
---------------
The default mode first opens one logical AUDSVC stream and submits a
480-frame all-zero quantum. The service must accept it without materializing
the kernel/backend stream. It then submits sixteen 480-frame square-wave
quanta and five
frame-aligned packets of 1, 239, 17, 310 and 33 frames. This bounded burst
crosses the two-period HDA start reserve and occupies part of the fixed
64-period ring without comparing QEMUs guest timer with its host audio thread
under TCG load. A final all-zero quantum must close the materialized backend
once without being written as PCM. The pattern exercises lazy open, real
idle, one-frame edges, packet/period independence and a partial drain tail
without adding diagnostic silence to the hardware stream. Expected signal
length remains 8,280 frames.

Invoke-QemuWavCapture.ps1 uses the shared Distribution headless runner with
four vCPUs and a fresh private copy of the five-partition installation image.
It works on Windows and Debian Linux, records QEMUs WAV audiodev, requires
normal guest poweroff and passes the WAV to Analyze-QemuWav.ps1. SourceRoot
may select a prepared image with a focused AUTOEXEC and a terminal shell
that executes it. AudioOnly changes only marker and WAV requirements; it
does not change the image boot configuration or suppress programs already
selected by that configuration. For a short audio-only run, the prepared
Test image must boot TERMINAL.R4X without /NOAUTOEXEC and its AUTOEXEC must
start services, run AUDIOD.R4X without /LONG, then power off. The standard
/HEADLESS-SUBSYSTEM desktop boot still starts its own subsystem probes. The default mode additionally requires both
R4GB long-run markers and its waveform analysis. OutputDirectory selects a
new evidence directory; existing recordings are never overwritten. Streaming
WAV files with zero RIFF/data lengths use the actual file end.

The analyzer identifies AudioDiag's stable equal-channel square-wave plateau
by amplitude, shape and expected duration. This keeps a longer or louder boot
or subsystem signal in the same WAV from merging with the diagnostic span. It
groups only short resampler zero crossings, requires the resulting signal span
to stay within 5 percent of the 8,280-frame source duration and detects the
known legacy signature from cluster spans. Its selftest contains a good
fixture, the old sequence of 480 signal plus 544 zero frames, an injected
sample-loss fixture and a mixed-audio fixture with louder unrelated audio.
Ring wrap and packet phase are covered by the HDA and AudioDiag host tests.

Lifecycle and HDA diagnostic
----------------------------
After the master-volume test has restarted AUDSVC, AUDIOD performs four fresh
Open/Write/Close cycles with a non-silent 256-byte partial-period packet.
Each cycle must materialize exactly one backend stream and return both logical
and materialized session counts to zero. The sequence proves replay after the
restart while backend drops, underruns, errors and failures remain unchanged;
the HDA close path clears every partial tail before the next generation.

AUDIOD then queries the Driver source in LOGSVC. A bounded `HDA.DIAG core`
record must name PCI selection, controller ID and GCAP streams, transport,
codec/AFG, analog route/pin and format. A bounded `HDA.DIAG run` record must
name IRQ and position modes plus separate write/underrun, FIFO/descriptor,
position-source mismatch/fallback, position/stream recovery, timeout/drain
and work-drop counters. `pos=lpib-fallback` is distinct from `dma+lpib` even
when the controller accepted a DMA position buffer. The standard
QEMU marker gate requires both records and the lifecycle result; HDA emits no
per-write, per-verb or per-IRQ normal log stream.

Long mode
---------
AUDIOD.R4X /LONG produces 6,000 quanta, or 2,880,000 frames/60 seconds. It
targets sixteen queued HDA periods and then submits when the reported backend
fill drops below that threshold. This deliberately follows device consumption
instead of QEMUs guest timer, because the emulated audio thread and guest
clock may drift under TCG load. The test therefore measures continuous ring
operation, not agreement between two emulator clocks.

Physical evidence export
------------------------
`AUDIOD /OUT=<path>` exports the current HDA driver records before the bounded
LogService window can advance. Candidate decisions, selected controller,
compact core and close-runtime records are mandatory. The AUDIOD result fails
if any class is missing or if the file cannot be written. `/LONG` and `/OUT`
can be combined; the path must not contain spaces.

Result separation
-----------------
The line beginning with "AUDIOD path" reports five independent deltas:
upstreamDropped, driverUnderruns, driverErrors, backendFail and silencePeriods.
A successful continuity run requires all five to be zero. Additional lines
show stream/service write latency, high water, refill count and final queue.
`AUDIOD idle` requires exactly one lazy materialization, two suppressed
silence writes and one idle close. `AUDIOD deadline` requires productive
deadline submissions/starts and zero new misses, callback-budget overruns or
queue rejections. No interrupt-by-interrupt or write-by-write log is emitted.
`AUDIOD lifecycle` and `AUDIOD HDA diagnostic` report the restart replay,
generation cleanup and the validated compact HDA snapshot.

---------------------

    Build.bat test
    pwsh -NoLogo -NoProfile -File Tests\Invoke-QemuWavCapture.ps1 -Profile Test
    ./Build.sh test
    pwsh -NoLogo -NoProfile -File Tests/Invoke-QemuWavCapture.ps1 -Profile Test

For the 60-second gate, place /LONG on the AUDIOD line of the local Test
AUTOEXEC, rebuild the Test image, run the headless acceptance, then restore
the default capture. The committed Test profile always uses default mode.

Short capture IRQ witness (0.81.17)
---------------------------------
Before idle/Close starts synchronous drain, AudioDiag waits at most 100 ms
for one submitted and started audio deadline job, checking once per ms.
The 8,280-frame signal is unchanged. A fast producer must not fail the
asynchronous-lane check merely because all writes precede the first IRQ.
A missing worker or timeout still fails; zero new misses, overruns, drops
and backend errors remain mandatory.

Kernel mixer ring positions (0.84.33 / Kernel 0.1.318)
---------------------------------------------------
The existing eight-stream general mixer snapshots bounded local cursors once.
Each source advances its own byte position and wraps at its actual ring edge;
there is no per-sample runtime remainder division. Valid source positions need
no initial remainder either. No heap, FPU or SIMD is introduced. A private
wider-input facade retains its original generic path and bounds. The canonical
eight-stream capacity is shared with the original core stream table.

The unity single-source direct copy and signed gain/division, addition order,
rounding, saturation and Work counters are unchanged. Only local copied cursors
advance; real read reservation, consumption after backend acknowledgement,
output ownership, backpressure, Busy/Close and driver completion stay with the
unchanged core. There is no new stream or lifetime registry.

174 bounded byte/counter comparisons run the complete previous and new mixers
on direct/scaled/multiple sources, different and odd wrap positions, short/tiny
rings, silence, signed extrema, saturation and partial tails. Original input
positions/ring bytes and output canaries must remain intact. The host link copy
only renames the previous private export symbols to avoid a duplicate-symbol
collision; the original snapshot and hashes remain. Original short AudioDiag
and its AudioOnly WAV analyzer provide the native SMP4 path. No new permanent
audio suite, long capture or microbenchmark is added. That qualification used
STANDARD Suite 2; the current method is in Diagnostics/SpectraStandardBenchmark.txt.
STANDARD does not directly measure mixing; no elapsed improvement is inferred from
the source change or one standard run. Evidence: Core/KernelAudioRing08433.json.

Bounded last-stream Close (0.87.66, HDA 0.3.45 / AUDSVC 0.1.17)
----------------------------------------------------------------
Ordinary HDA Idle no longer sleeps through DMA drain or waits for Work inside
a Close RPC. One resident normal Work continuation advances the drain even
if the caller stops waiting. It retains the original 400 ms drain and 100 ms
refill-retirement limits, including initial queue delay, and checks the real
output/reset identity. Success requires consumed caller PCM, quiet hardware,
actual refill retirement and the terminal continuation's completed/released
ticket. New accepted PCM cancels the old intention. HDMI control/probes remain
independent; full driver Stop/shutdown retains its physical quiescence path.
No normal audio deadline budget is borrowed for this continuation.

Tracked Close keeps its original immediate Busy response and 100 ms per-RPC
contract. Legacy Close keeps one copied request/client/session-generation key
in AUDSVC's service loop for at most 500 ms, within the unchanged 1000 ms legacy
caller timeout. Other service requests remain available. A duplicate cannot
replace the original response or restart its deadline. Pending or expired
work cannot count as successful cleanup, and a late IPC publication does not
prove delivery. The service loop polls only while an actual Close is pending.

The first HDA45-only local integration exposed a legacy Close Busy regression
before HDA diagnostic export; that original failed run remains recorded. The
HDA45/AUDSVC17 integration passes unchanged original GAP 1440, default 8280 with
four close/restart cycles, HDA evidence, PROGRESS 480 and both 60-second SNES
owners on actual KVM with four CPUs. The unchanged native mixed fixture on
OssiPC/16 CPUs also passes eight GAP cases, three exact Explorer reaps,
32 correct reads, three joins and four AP worker classes. Its first-content
latencies are 542/172/221 ms in this run; the earlier failed 100 ms Close and
8.8 s folder result remain separate originals, without blanket attribution.
Both original 60-second SNES owners and the original native 8280/GAP/PROGRESS
and HDA cooperation checks pass with HDA45/AUDSVC17. Physical visibility,
hearing and input latency are explicitly skipped; no acoustic or isolated
speedup conclusion follows from these automated checks.
