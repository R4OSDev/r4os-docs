R4OS C ABI
==========

A C R4X project includes:

```c
#include <r4os/r4os.h>
```

The SDK startup code exports `R4XStart:1`, validates the start context and
calls the C application entry with an initialized `R4App`. Platform groups
use the same generated layouts and function signatures as Zig.

Every optional group or function has an explicit availability check. String
and buffer lengths are byte lengths. Borrowed pointers remain valid only for
the operation documented by the Contract; owned resource wrappers must be
closed, joined, released or reaped exactly once.

Independent Runtime-R4Ls provide their C header from the library repository.
A consumer initializes the library-local client from the same R4XStart
context and requests a minimum table revision. There is no central C table
for R4STD, R4IMG or R4FONT.

The C headers are generated or checked from `Repositories/Contract/` and
`Repositories/SDK/Shared/C/`. Normal consumers do not copy these headers into
their own source tree.

Technical projection (0.86.48)
-----------------------------
The Contract's public C header now includes abi_technical_generated.h.
The existing ABI reflector derives its driver/protocol/DMA/USB, service and
other technical records from the same append-only Zig definitions used for
Rust. There is no second handwritten technical C schema. write/check owns
both projections; hand editing generated headers is not supported.

Wire enums use integer typedefs of their exact canonical width. R4AppProfile
is uint8_t and R4ErrorDomain is uint16_t; their former ordinary C enum widths
did not match Zig/Rust. Use the typedef names, not enum tags. Existing
enumerator names and values remain; new typed enum constants use R4ABI_.
C keywords in field names gain one trailing underscore, such as register_.
Other field names, offsets and callback meanings retain their contract.

The current central callback contract has integer/pointer parameters and
integer, void or pointer returns. It has no direct float/vector arguments or
results and no structures passed or returned by value. Pointer-addressed
records, optional callbacks and nullable pointer results remain explicit.
External GL/Vulkan and local library call forms need their own qualification;
this central projection is not a general direct-float ABI bridge or a C/Rust
driver lifecycle qualification.

Pooled userland heap (SDK0.64.69)
--------------------------------
<r4os/heap.h> supplies explicit R4Heap contexts for normal R4X images:
r4_heap_init(&app->system,&heap), aligned alloc/malloc/calloc/realloc/free,
one locked snapshot of all VM-allocator metrics, and explicit heap finish.
The C builder links the same SDK-owned vm_allocator.zig core used by Rust.
Kernel VM/task ownership remains authoritative; no kernel allocator is copied.
Context admission and every operation check the current exact instance and
generation before touching allocation metadata. This module-local default is
not a shared R4L-global allocator; caller-owned library heaps are separate.

Zero allocation returns NULL; invalid alignment and checked arithmetic overflow
fail before VM work. Failed growth preserves the original buffer. Logical free
can retain cached/pending VM regions. Finish irreversibly closes allocation
admission: join users and free buffers before retrying. Result0 requires all
exact region/notification release ACKs;1 is busy/live and2 is pending physical
release. A partial release never permits payload-header rereads or reuse.
Normal root return leaves final cleanup with the kernel until task retirement.
The lower direct r4sys_vm_* primitives remain available; their buffer helper's
size/alignment/page-rounding overflow is now checked as well.
