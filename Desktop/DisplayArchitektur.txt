Layers
------

The native graphics architecture is tracked in GrafikZielbild079.txt and
GrafikRoadmap079.txt. Software integration through 0.79.24 is described in
GrafikKomposition07920, GrafikPrimitive07921 and GrafikMehrschirm07924 (.txt/.json). These are historical software checkpoints. Current physical NVIDIA evidence
and its limits are linked above; local software checks do not renew it.

- Boot display: early and fatal output on the Limine framebuffer.
- Display manager: active backend, geometry and presentation.
- Software surfaces: validated XRGB32 pixel storage.
- R4DRAW: public drawing, font, image, surface and frame operations.
- R4DESK: windows, events, desktop state and remote-frame access.
- Desktop R4X: composition, policy and visible user interaction.

Applications draw through R4DRAW into their assigned targets. The desktop
owns window placement, clipping, damage, z-order and final presentation.
Early boot output remains separate and is invalidated when the normal
desktop takes ownership.

Software surfaces use XRGB32. Width, height, pitch, clipping and source/
destination rectangles are validated before pixels are published. Remote
desktop services consume completed frames through R4DESK and return input
through the same contract; they are not a second display owner.

Asynchronous native mode changes (0.79.13)
-----------------------------------------

R4DRAW ABI13 submits a validated primary configuration to a separate common
worker. That worker retains the old and new SYSTEM shadows, serializes
display execution and coordinates driver receipts, geometry publication,
confirmation and timed rollback. The R4D owns GPU allocation, programming
and proof that a retired image is no longer in use. Timeout alone never
permits its memory to be reused. Driver work remains independently runnable.

The display manager publishes active dimensions, pitch and the public drawing
target under the same state owner after the matching receipt; the original
boot capture is immutable. Input reads one atomic size projection, so mouse
packets, snapshots and cursor bounds follow the new output without taking a
display lock in an IRQ. Desktop output events also update layout and retire
an obsolete scene allocation through the existing geometry helper. Settings >
Display launches Appearance /DISPLAY for progressive SDR mode selection,
initialized test-pattern buffers and Keep/Revert controls. Accepted references
and the 15-second return timer stay with the common owner after the app closes
its own reference. The app polls the actual transaction, refreshes the catalog
after completion and requests rollback on close; it never infers hardware
recovery from elapsed time. Since 0.79.24, kept output layouts and modes persist in DISPLAYS.R4S; see GrafikMehrschirm07924.txt/.json. NVIDIA
integration and validation limits: Drivers/GrafikScanout07913.txt/.json.

Multiple outputs and logical coordinates (0.79.24)
-------------------------------------------------
Desktop owns up to eight current outputs with independent workers, damage,
swapchains and completion. Coordinates are signed logical values; physical
rasters use per-output scale in 120ths and one of four rotations. The shared
grid contract reaches both the CPU renderer and the native GPU sampler.
Cursor movement, cloned/extended views, window rescue and scene invalidation
use the same transform. The primary workspace can move between outputs.

WINSVC carries bounded, idempotent display-control requests. Appearance
selects arrangement, mode/refresh, scale, rotation, primary, clone and enable.
Desktop owns the timed keep/revert decision and restores pending state on a
service restart. DISPLAYS.R4S retains stable PCI/connector/EDID identities;
unknown receivers remain session-only. Native restoration uses the common
mode queue and retains old/new BO references until actual driver receipts.

The native driver shares its RM graph, CE and Core while owning separate
Window/WIMM channels, images, flips and statistics per head. A stale exact
output target never falls back to another output. Additional mode waits do
not hold the primary display execution owner. Hotplug physically retires the
affected head before common removal; another output can continue presenting.
Window loss retains unproven consumers and isolates the affected output;
reset recovery remains the separate 0.79.30 step. Additional heads use
composition and software cursors. Detailed limits and physical follow-up:
GrafikMehrschirm07924.txt/.json and ExFiles/Reports/OssiGPU.txt /0.79.24.

Physical console scrolling
--------------------------

After heap initialization the boot-display owner may allocate one resident
packed-pixel shadow for the console lifetime. It uses width * height * 4 bytes,
capped at 64 MB and 1/32 of usable RAM; allocation failure keeps the existing
cell redraw path. No console/log callback allocates memory. A full clear
establishes the shadow without reading the device framebuffer. Glyph writes
update it and present only their cell; scrolling moves existing RAM rows,
fills the exposed bottom line and presents the text rectangle. Changing font
scale invalidates the logical cells while retaining the exact packed image.
External splash/desktop/crash writes invalidate both views until a new clear.

The shadow needs 8294400 bytes at 1920x1080 and 33177600 bytes at 3840x2160.
At 1920x1080 with scale two, one scroll still presents 2058240 text pixels.
It performs no glyph-row evaluation; the previous cell path evaluated 128640
glyph rows. Pixel movement and device writes remain necessary, so these
counts do not claim an equivalent wall-clock or FPS gain.


Damage and presentation
-----------------------

The Desktop retains up to eight dirty regions. Overlapping regions are merged;
when a ninth region arrives, only the pair with the least additional bounding
area is merged. The persistent damage tracker and final presenter collector
share this policy. An explicitly invalidated complete scene remains the
full-frame fallback. It composes each retained region only through scene owners whose
bounds intersect it. Background, wallpaper, grid, desktop items, windows,
taskbar, menus, dialogs and cursor keep their existing z-order; complete
non-intersecting layers and windows are rejected before their paint work,
while desktop-item bounds are checked before icon loading and rendering.
An inactive window is also skipped when its entire damaged frame intersection
is covered by one opaque higher window. Partial coverage preserves normal
painter order; active windows remain last. Move, hide, minimize and focus
changes are evaluated against current window geometry on every composition.

R4DRAW slots 33 through 35 are the canonical present contract. A request
identifies one XRGB32 source generation, its dimensions and stride, up to
eight damage rectangles and an optional input tick. The result reports the
single present generation, exact region and pixel work, backend, fallback,
error, synchronous fence/completion and input-to-present ticks. Capabilities
name both the selected backend and the CPU fallback. Every region is
validated before the first visible write. Unsupported, absent or failed
external backends therefore copy the complete accepted generation through
the boot framebuffer without partial external/CPU mixing.

The old single-rectangle stride slot 32 and packed-source slot 9 remain
compatibility entries, but both feed the same presenter and DisplayManager.
Only DisplayManager owns productive present counters, fences, backend choice
and fallback; the Surface and compatibility frame lifecycle keep no parallel
statistics.

Hosted application frames
-------------------------

R4DRAW-v5 extends the append-only table at slots 36 through 38. A producer
starts a damage generation with up to eight exact client rectangles. The
kernel retains one immutable full base plus bounded immutable deltas; it no
longer deep-clones the committed command/resource payload for every small
change. A reader can request metadata and bytes for one generation or use the
existing full-frame read as a flattened compatibility view. Owner handles,
generation numbers and retired-reader lifetimes remain validated at every
read boundary. A full generation compacts the chain after at most 31 deltas.

R4DRAW-v8 appends slots 41 and 42 for a standalone replacement generation
and its stream telemetry. A replacement still carries the exact changed
client rectangles, but its commands and resources describe the complete
current frame and supersede the previous chain. Unreferenced old generations
are released immediately; a reader-held root is retired until its final
release. Commit failure, cancellation or allocation failure leaves the last
complete generation active. The counters expose live, superseded, coalesced
and reader-retired generations plus native-XRGB command/resource work and
current/peak frame bytes.

`GuiIndexed8Resource` carries a fixed header, 256 XRGB palette entries and an
at-most-128x128 indexed source tile. The command records destination geometry
separately, so integer and fractional scaling do not require producer-side
XRGB expansion. Desktop appends a direct successor delta to its active cache,
rebases only the new resource offsets and invalidates only the supplied
regions. Missing generations, unsupported tables, invalid payloads and
allocation failure retain the previous complete frame and use a bounded
full-snapshot retry. Rendering rejects non-intersecting commands before
touching their payload and resolves Indexed8 pixels only inside the active
scene paint clip. Equal integer scaling (including 1:1) expands each visible
source pixel once, fills its horizontal run and copies completed rows. Other
ratios retain global nearest-neighbour mapping. For an 8x8 tile enlarged to
128x128, this reduces source/palette visits from 16384 to 64; the 16384
destination writes remain necessary. No extra image buffer is allocated.

Each complete Desktop snapshot owns an optional ordered spatial tree over
blocks of sixteen commands. A small paint clip visits intersecting blocks
instead of scanning every command for every region. Append generations update
only the changed suffix and its ancestors; replacement and full reads build
the index before publication. The tree stores local bounds and no resource
pointers. Its lifetime follows the existing command/resource buffers and
shared-raster leases; moves do not rebuild it. Allocation failure selects the
complete ordered replay without discarding a frame.

Text bounds are derived once from the UTF-8 resource, independent of optional
producer metrics. Built-in cells use exact dimensions; imported fonts use
the renderer's maximum cell dimensions so font revision changes remain safe.
During clipped replay, whole hidden lines and right-hand suffixes skip UTF-8
decoding and glyph lookup. Intersecting multibyte glyphs retain their cell
positions. Shape masks are cropped to the scene/client intersection before
rasterization and allocation, with a blur-radius halo for outer and inset
shadows; coverage is still sampled in the original command coordinates.

Owner tests compare indexed and complete painter output, occlusion changes,
glyph edges, antialiased curves and clipped shadows. Deterministic work cases
retain eight regions and ten total pixels for nine scattered single-pixel
changes spanning 1920x1080, reduce command visits from 32768 to 240 for eight
clips in a 4096-command frame (226 tree-node visits), and rasterize one mask
pixel for a 2048x2048 shape with one damaged pixel using a two-byte scratch
budget. Four coincident opaque windows require one window replay instead of
four. These are software work counts, not a measured hardware FPS gain.

`GuiXrgb32Resource` keeps native source pixels, stride, guest geometry and
the complete viewport together in an at-most-128x128 tile. The Desktop never
turns this command into color runs: exact-size views use row copies, integer
views expand and repeat rows, and fractional views derive every sample from
global guest/view coordinates so tile seams remain identical. A replacement
snapshot is swapped atomically and its exact damage continues to bound
composition and final presentation.

R4DRAW-v9 appends six optional shared-raster slots. A producer owns a bounded
XRGB32, Indexed8 or Alpha8 resource with three backing buffers. Map-write
selects only a buffer without frame or reader references; publish freezes its
new raster generation. A GUI frame then carries only an 80-byte descriptor
per at-most-128x128 destination block. Desktop acquires each distinct
generation once, swaps the complete snapshot atomically and releases the old
lease afterwards, so the full image is neither copied into kernel frame
storage nor copied again into the Desktop snapshot. Producer death closes
new writes while existing frame/reader references keep exact bytes alive;
Desktop restart, replacement, cancellation and OOM all converge on the same
reference-counted cleanup. If all three buffers are busy or any optional slot
is unavailable, the previous copying frame path remains the bounded fallback.
`GuiFrameStreamInfo` v2 exposes publish/acquire/release, backpressure,
published/acquired/live bytes and avoided frame-copy bytes while preserving
the v1/112 prefix.

The subsystem-host regression measurement keeps this gain explicit. At
256 x 224 XRGB32 the former four copied tile resources occupied 230016 bytes
per changed frame; the shared frame carries four descriptors totaling 320
bytes after one 229376-byte producer upload. At 512 x 224 the corresponding
figures are 460032 and 640 bytes after one 458752-byte upload. Thus the
kernel-frame-to-Desktop-snapshot resource traffic falls by 99.860879 percent
in both cases. A 64-frame 256 x 224 run verifies one resource creation, 64
maps and publications, 256 descriptors, byte-identical pixels and no legacy
XRGB resource. Kernel stream counters independently report published,
acquired, live and avoided bytes; these are measurements of the software
pipeline and make no graphics-driver or pageflip claim.

Desktop text uses a fixed direct-mapped cache for 16 font layouts and 256
monochrome glyph-coverage snapshots. The key contains font id, codepoint and
the R4DRAW font-catalog revision; foreground and background colors are
applied only during the clipped blit. R4DRAW-v7 appends the live revision at
slot 40. Every completed font reload advances it, so reused ids cannot expose
stale layout or coverage. Older API tables use the SDK's stable revision 1
and retain their existing row fallback.

Terminal windows keep a fixed 16-KiB raw-output snapshot plus compact
descriptors for at most 256 visible rows. If the new output has the old bytes
as an exact prefix and instance, geometry, font, codepage, scroll, colors and
clear generation remain stable, only the suffix is parsed. Visible rows are
then compared and only changed row rectangles plus old/new cursor rectangles
enter the regional present path. Ring movement, scroll jumps and state or
layout changes use the bounded full rebuild. Headless counters expose cache
hits/loads and terminal full/incremental refreshes, parsed/skipped bytes and
changed/skipped rows; the cached glyph is also checked against an exact pixel
hash.

Backend inventory and primitive composition (0.79.21)
---------------------------------------------------

Limine bootfb remains early/fatal output and the generic software fallback.
DISPBLIT copies software pixels; VirtioGpu owns its QEMU scanout. NVIDIA
owns native GPU work, allocations and private scanouts behind common owners.
Physical NVIDIA activation still requires the existing qualification policy.

Desktop captures the same scene as bounded fills, glyphs and image quads.
Without RemoteFrame readers it allocates no CPU-painted layer pixels.
Content-keyed ARGB atlases keep converted glyphs, masks and image sources;
CPU curve/shadow rasterization stays bounded by existing damage/shape limits.
R4FONT owns glyphs; R4IMG owns decoding. Cold or dirty sources upload through
a fixed 1 MB staging image; unchanged sources remain resident. Adjacent
compatible draws share lists of up to 16 commands without changing order.

DEVICE_V1:7 adds render_submit_list; R4DRAW21 appends one list-submit slot.
One common queue fence retains the complete source/target pair. NVIDIA
uploads up to 16 KB of descriptors/vertices and emits one bounded GR stream
with one completion. The shader/packet cache remains 128 KB; the graph's
private staging grows to 16 KB while FIFO allocations remain 12 KB.

DEVICE_V1:8 adds bounded swapchains and shared presentation eligibility.
An eligible linear native XRGB output is directly scanned when it is the sole active native output; the final CE copy
is omitted. The desktop still composes its scene into that output. Menus,
windows, software cursor and capture choose composition/copy+flip instead.
BEGUN/IRQ establishes visibility; FINISHED and DMA withdrawal retire direct
sources. Close restores a private full image before releasing the source.
Details and physical limits: GrafikSwapchains07922.txt/.json.
Failure discards the capture and reconstructs the complete software scene;
unretired GPU resources remain owned. Without a qualifying native provider,
the software desktop continues through bootfb, DISPBLIT or Virtio.
Detailed budgets, sampling semantics and proof limits:
GrafikPrimitive07921.txt/.json; preceding composition ownership in /07920.

The remote XRGB32 shadow is a readback product, not part of local display
presentation. R4DESK slot 56 accepts the same bounded region generation, but
keeps a bounding dirty rectangle in the legacy reader metadata. RDPSVC,
Spectra CHECK REMOTEFRAME and other readers acquire a remote-frame consumer for their actual
lifetime. The first consumer wakes Desktop and causes a complete publish;
after the last release the live shadow and mapped snapshots are discarded.
Local-only frames therefore neither allocate nor copy a second full-screen
image. Frame revision, dirty union and stable map generation retain their
existing meaning while a consumer is active.


Direct drawing and presentation ownership (0.78.76)
-------------------------------------------------
The public clear, rect, text and text_font operations now draw through
DisplayManager and mark actual display use. Rectangles and glyphs clip signed
coordinates; each text call holds one font-catalog view and uses the selected
or explicit font, UTF-8 scalars, glyph advances and foreground/background.
Hosted GUI targets and the separate boot/fatal console keep their ownership.

All productive DisplayManager writes share a preemptible, nonblocking
try-admission guard. An overlapping presentation returns unavailable without
pixels or a success fence. Legacy void drawing requires exclusive fullscreen
ownership and does not mark use on a collision. Completed statistics are
copied under the short SMP program-state owner. Pixel stores, including WC
stores, finish before published completion and before another CPU can write.
Each successful regions call advances one generation/fence; this represents
copy completion and does not promise VBlank synchronization or page flipping.

DisplayBlit admission and the in-flight registration reference are atomic
against cleanup. A call retains its copied descriptor, owner, generation and
name; cleanup refuses a busy registration. The synchronous callback runs
outside the short state owner, and its completion cannot affect a later
registration. The existing driver-manager shutdown sequence is retained.

Color pipeline (0.79.25)
-----------------------
R4GFX COLOR_V1 owns explicit source/output color, linear FP16 composition,
ICC/VCGT and SDR/HDR conversion. Desktop retains separate SDR capture pixels.
NVIDIA color modes bind XR24/XR30 images and link metadata to the common
mode transaction; unsupported chains retain SDR fallback. Per-monitor color
settings use COLORS.R4S and the existing timed display controller. Detailed
contracts, limits and software evidence: GrafikFarbe07925.txt/.json.


Variable refresh (0.79.26)
-------------------------
R4GFX owns receiver/timing admission, adaptive swapchain planning, bounded
hardware observations and per-monitor REFRESH.R4S preferences. Desktop renews
the shared 1.5-second presenter lease; Kernel holds copied metadata only.
NVIDIA confirms link/RM/Core transitions before publishing active/fixed.
Capture, display transitions, faults and multiple active heads require fixed
refresh. Detailed contracts, limitations and evidence: GrafikVRR07926.txt/.json.
