R4OS display architecture
=========================

Layers
------

- Boot display: early and fatal output on the Limine framebuffer.
- Display manager: active backend, geometry and presentation.
- Software surfaces: validated XRGB32 pixel storage.
- R4DRAW: public drawing, font, image, surface and frame operations.
- R4DESK: windows, events, desktop state and remote-frame access.
- Desktop R4X: composition, policy and visible user interaction.

Applications draw through R4DRAW into their assigned targets. The desktop
owns window placement, clipping, damage, z-order and final presentation.
Early boot output remains separate and is invalidated when the normal
desktop takes ownership.

Software surfaces use XRGB32. Width, height, pitch, clipping and source/
destination rectangles are validated before pixels are published. Remote
desktop services consume completed frames through R4DESK and return input
through the same contract; they are not a second display owner.

Damage and presentation
-----------------------

The Desktop composes only scene owners whose bounds intersect the current
damage rectangle. Background, wallpaper, grid, desktop items, windows,
taskbar, menus, dialogs and cursor keep their existing z-order; complete
non-intersecting layers and windows are rejected before their paint work,
while desktop-item bounds are checked before icon loading and rendering.

For a sub-rectangle of the full scene, R4DRAW slot 32 carries the scene width
as the source stride. Thus one narrow rectangle remains one ABI call instead
of one call per row. Slot 9 remains the packed-source compatibility contract.

The remote XRGB32 shadow is a readback product, not part of local display
presentation. RDPSVC, RFDIAG and other readers acquire an R4DESK remote-frame
consumer for their actual lifetime. The first consumer wakes Desktop and
causes a complete publish; after the last release the live shadow and mapped
snapshots are discarded. Local-only frames therefore neither allocate nor
copy a second full-screen image. Frame revision, dirty union and stable map
generation retain their existing meaning while a consumer is active.
