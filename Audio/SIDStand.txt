SID in R4OS
============

SID support is split into independent components:

- `Repositories/Drivers/SID/` owns the loadable SID engine and its runtime
  state.
- `Repositories/Protocols/AudioSid/` owns the SID protocol role.
- `Repositories/Apps/R4Synth/` is the normal player and consumer.
- R4AUDIO exposes the public operations required by applications.

There is no productive second SID implementation in the kernel. The driver
owns register state, model selection, playback frames and cleanup. Protocol
parsing and application presentation remain outside the driver.

The current implementation targets the documented 6581/8580 behavior needed
by R4Synth. Hardware-faithful analog behavior is not promised; deterministic
software output and a clean component boundary take priority.

SID.R4D resolves model, register and mirrored-I/O operations through the
installed AudioSid.R4P using the append-only DriverApi v18 protocol bridge.
The kernel reapplies the configured SID model after protocol loading, so the
driver never needs an embedded substitute protocol.

Each successful play step produces one PCM block for the active audio
backend. If that backend reports backpressure, the block remains pending and
the caller retries the same frame. Hard backend or runtime failures are
returned unchanged. Stop, release and error cleanup share the same
idempotent pending-state reset.
