R4OS concurrency and responsiveness
===================================

The scheduler is preemptive. Wait queues, completions and dedicated workers
move blocking storage, filesystem, service and driver work out of IRQ and
reactor hot paths. Synchronous public calls may wait for completion but must
not secretly execute a second inline runtime path.

Rules
-----

- IRQ handlers perform bounded work and defer longer operations.
- A lock is not held across I/O, yield, wait or application callback.
- Wake producers publish state before signalling the matching wait queue.
- Completion at a timeout boundary wins when it can be proven.
- Desktop and drawing objects are owner-thread-only unless the API explicitly
  states otherwise.
- Service reactors process only short nonblocking requests; session work uses
  bounded workers or explicit asynchronous completion.

Module tasks may use SIMD. The scheduler saves a CPUID/XCR0-sized FPU state
for SIMD-capable tasks. The standard module target assumes AVX2; the kernel
is built without SIMD and remains ReleaseSafe.

Scheduler work sets
-------------------

The stable Task registry owns identity and inventory only. Three intrusive
projections derive from it under the IRQ-disabled state-transition boundary:
the Ready FIFO, a stable ordered finite-deadline queue, and deferred-reap
candidates. Runnable selection and starvation diagnostics visit Ready tasks;
timeout dispatch starts at the deadline head and stops at the first future
wait. Equal deadlines retain enrollment order. One timer IRQ wakes at most 64
due tasks, leaving an ordered and diagnosed backlog for the next delivery. A
reaper pass visits only the candidates present at its start. Blocked unrelated
tasks do not increase these hot paths.

Active execution retains the periodic scheduler source needed for preemption.
When the current task is truly idle, HPET or the calibrated LAPIC is switched
to a one-shot for the queue head; an empty deadline queue disarms it. An
external wake cancels the pending shot and reevaluates the head. Long deadlines
use bounded hardware checkpoints. PIT systems remain periodic, while logical
ticks, watchdog budgets and runtime accounting continue on the same epoch and
do not count IRQ deliveries as elapsed time.

Priority selection takes the first task of the best class from the Ready
FIFO; every eighth cooperative selection retains the existing cross-priority
fairness turn. A wake of a higher-priority task publishes Ready state and a
reschedule request while still inside the producer's critical section. The
request can bypass the normal 30 ms quantum, but an actual context switch is
allowed only at the safe IRQ-exit boundary after WaitQueue locks, handler work,
and EOI have completed. Kernel instruction pointers and active preemption
guards keep the request pending instead of violating lifecycle or lock rules.
