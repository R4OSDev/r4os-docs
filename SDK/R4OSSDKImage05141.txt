R4OS SDK-Imagepaket 0.51.41
===========================

Zweck
-----

0.51.41 installiert das SDK als Buildzeitpaket in das R4OS-Image. Das Paket
liegt im laufenden System unter:

```
C:\R4OS\SDK\
```

R4CODE und R4BUILD sollen spaeter diesen Pfad lesen. Sie besitzen keine
private SDK-Kopie unter `C:\SOFTWARE\R4CODE\`.


Quelle und Ziel
---------------

Die Repo-Quellen bleiben die Wahrheit. Der Image-Build erzeugt nur einen
installierten Snapshot:

| Repo-Quelle | Image-Ziel |
| --- | --- |
| `Code/System/SDK/Shared/C/include` | `C:\R4OS\SDK\Include\C\` |
| `Code/System/SDK/Shared/C/src` | `C:\R4OS\SDK\Startup\C\` |
| `Code/System/SDK/r4os/linker` | `C:\R4OS\SDK\Linker\` |
| `Code/System/SDK/Templates` | `C:\R4OS\SDK\Templates\` |
| `Code/System/SDK/BuildProfiles` | `C:\R4OS\SDK\BuildProfiles\` |
| `Code/System/SDK/Toolchains` | `C:\R4OS\SDK\Toolchains\` |
| `Code/System/SDK/Contract` | `C:\R4OS\SDK\Contract\` |

`Code/System/SDK/Contract` bleibt die ABI-/API-Wahrheit. `C:\R4OS\SDK\Contract` ist nur
der installierte Snapshot fuer interne R4OS-Werkzeuge.


Installierte Inhalte
--------------------

- C-Header unter `Include\C\`.
- C-Startup-Stub `Startup\C\r4xstart_startup.c`.
- Linkprofil `Linker\r4os_module.ld`.
- Templates unter `Templates\`.
- Buildprofile unter `BuildProfiles\`.
- Contract-Snapshot unter `Contract\`.
- Toolchain-Zielpfad `Toolchains\C\` mit Markerdatei, aber noch ohne
  Compiler.

Das erste SDK-Template fuer den internen R4CODE-Block ist:

```
C:\R4OS\SDK\Templates\R4OS\R4X_C_Console\
```

Das erste Buildprofil ist:

```
C:\R4OS\SDK\BuildProfiles\R4X_C.ini
```


Nicht Installiert
-----------------

Nicht Teil des R4OS-SDK-Imagepakets sind:

- R4CodePad
- `DevTools`
- `Build.bat`
- QEMU-/Runner-Konfiguration
- Windows-/Linux-Hostskripte
- Git-/Push-Helfer
- Build-Caches
- ein vorgebauter C-Compiler

Das ist Absicht: R4OS bekommt ein SDK-Paket fuer interne Werkzeuge, keinen
versteckten Host-Buildpfad.


Abnahme
-------

`DevTools/Scripts/CreateImageAddList.zig` sammelt die SDK-Baeume direkt aus
`Code/System/SDK` und `Code/System/SDK/Contract` in `Release/image-adds.txt` ein. Dadurch gibt
es keine zweite Quelle unter `Injection/`.

Der statische Check `CheckR4OSSDKImage05141.zig` prueft:

- die erwarteten Quell- und Zielpfade,
- den installierten Contract-Snapshot,
- das erste C-Template,
- das erste C-Buildprofil,
- keine SDK-Duplikate unter `C:\SOFTWARE\R4CODE`.
