R4F system font format
======================

R4F is the compact bitmap-font format used for installed R4OS system fonts.
It is separate from webfont containers handled by the independent R4FONT
runtime library.

An R4F file contains a validated header, font metrics, a codepoint-to-glyph
mapping and fixed bitmap rows. The display/font loader rejects inconsistent
offsets, dimensions or truncated glyph data before publishing the face.
System fonts are installed below `C:\R4OS\FONTS\`; the distribution owns
their generated image payload under `Repositories/Distribution/Assets/`.

The kernel keeps a small built-in fallback font for early and fatal output.
That fallback and the external R4F catalog deliberately do not share a source
module: host font tools must not import kernel code.

R4DRAW exposes installed font enumeration, measurement and drawing. Runtime
applications should not parse R4F directly unless they are a dedicated font
tool or diagnostic.

Runtime catalogue publication (0.78.49)
--------------------------------------
Kernel font enumeration and glyph data belong to one immutable catalogue
snapshot with its own nonzero revision. R4DRAW retains that snapshot for a
complete metadata, measure or bitmap operation. Two resident banks bound
preparation and retirement; readers retain the old bank after publication,
and a competing reload or attempted reuse of a still-borrowed bank reports
unavailable. The native private layout at 0.83.21 reserved 3,605,016 bytes
per bank. The current bounded capacity is documented below for 0.85.40.
The large glyph payload is uninitialized resident BSS, populated only for
registered slots; it is not duplicated as initialized kernel-file data.
The small empty state contains no glyph payload allocation.

Reload prepares a complete replacement while file I/O remains outside any
no-sleep lock. A task unwind token protects the writer reservation and read
leases from hard retirement. Directory I/O errors are distinguished from end
of enumeration. Read/admission/capacity failures discard the unpublished
candidate and retain all former IDs, pixels and revision; invalid font files
remain explicitly rejected entries under the existing format policy.
Successful publication switches data and revision together, then R4DRAW
notifies consumers. Old storage is reused only after its final reader exits.
The early builtin font remains available without filesystem initialization.

The focused owner probe retains an old reader across a successful two-font
reload, verifies its old face, and defers reuse of that bank. A subsequent
injected directory-admission failure after one staged font preserves the
entire published catalogue, revision and notification count. Existing UTF-8
measurement and bulk/row/pixel equivalence cases continue to pass. The host
font-test wrapper keeps kernel-local lifetime imports inside their owner
module root; the underlying tests remain in kernel/font.zig.

The current native owner, migration evidence and its narrower validation
scope are documented in Core/KernelRustInput.txt and KernelRustInput08321.json.
The focused retained-reader/reload-failure probe above is historical evidence
from 0.78.49, not a repeated concurrency acceptance for the Rust migration.


Schriftlader ab 0.78.65
----------------------
Kernel 0.1.129 prueft BDAT-/GMET-/GMAP-Datensatzanzahlen per verbleibender
Tabellenlaenge, bevor er sie multipliziert. Bitmap-Payload beginnt hinter
den vollstaendigen Datensaetzen; Glyphenindizes bleiben innerhalb der
angegebenen Glyphenanzahl. Headergroesse muss in die deklarierte Datei passen.
Die Differenz der i16-Glyphenkoordinaten wird als i32 berechnet. Negative oder
mehr als 40 Pixel breite Boxen werden als unbrauchbare Bitmapmetrik abgewiesen.
Fehlerhafte Fonts bleiben als nicht renderbare Katalogeintraege sichtbar;
der bekannte Ersatzfont und nachfolgende gueltige Eintraege bleiben benutzbar.
Die Katalogveroeffentlichung aus 0.78.49 bleibt bestehen.

R4FONTs FNT-Import uebergibt jede Bitmap genau einmal an owned_glyphs. Nach
dem erfolgreichen Append ist der lokale errdefer deaktiviert; scheitert die
folgende RasterGlyph-Listenallokation, raeumt ausschliesslich der Besitzer auf.
Dies gilt fuer V1-Bitmap, V1-Vektor und V2/V3. FON-/NE-Header, Ressourcentabellen
und verschobene Ressourcengroessen werden mit breiter, gepruefter Arithmetik
an die Eingabelaenge gebunden. Verschiebungen ausserhalb der Zielbreite oder
mit verloren gehenden Bits werden abgewiesen. FONTS 0.1.4 bindet diese korrigierte
Importlogik ein. Der R4FONT 0.2.2-Decoder verlangt 20 Bytes, bevor er das WOFF-/
WOFF2-Groessenfeld ab Offset 16 liest. Eingaben mit 18/19 Bytes bleiben unabhaengig
vom nachfolgenden Byte. API, Tabellenlayouts und Fremdbibliotheken sind gleich.
Der Bytebestand der eigenen Bridge ist im vorhandenen Vendormanifest erneuert.

Unicode bitmap maps and stock repertoire (0.85.40)
-------------------------------------------------
GMAP.codepoint is a Unicode scalar, never a CP437/1252 byte. New bitmap
writers use CHARSET_UNICODE=FFFF in each record. FACE flags retain a legacy
import's source repertoire plus UNICODE; older 437/1252 GMAP tags are accepted
only as matching FACE provenance. They never trigger a second conversion.
Previously imported raw-byte mistakes remain ambiguous and need reimporting.
FNT ANSI=0 maps through the exact R4STD Windows-1252 table; OEM=FF explicitly
uses R4OS's US CP437 policy. Windows OEM is locale dependent, so FF alone does
not prove an arbitrary foreign OEM font is CP437. DEFAULT=1, SYMBOL and other
charsets fail until an actual codec/policy exists. Undefined 1252 slots are
omitted. OEM control pictures use their separate Unicode graphic scalars.
Preview samples are strict UTF-8; bad charset/text leaves pixels unchanged.
Unavailable source glyphs are omitted from the preview.

The native first-face bitmap backend rejects surrogates, values over10FFFF,
unknown/contradictory charset tags, nonzero record flags/face IDs, conflicting
scalars for the same glyph ID and duplicate bitmap payload IDs. A repeated
scalar may retain different glyph IDs; lookup stably chooses the lowest ID.
Map records are bounded to1024, cache glyphs to512, input to128KB, and bitmap
dimensions stay at40x40. A private cache is108564 bytes and one catalogue bank
is7185944 bytes. Glyph payload/template initialization remains resident and
in place; no large glyph array is copied onto a task stack. Public R4DRAW
ABI, R4F1 version and catalogue read/write lifetime remain unchanged.

All fourteen stock fonts now contain exactly257 scalars:223 CP437 printable
characters,32 distinct historical PC pictures, Euro and U+FFFD. C0/DEL text
controls keep their meaning. Terminal8/16 preserve joined line/block cells;
R4Sans preserves proportional UI leading, not a terminal grid. Original
ASCII is unchanged. The pinned font8x8 public-domain originals, bit order,
corrected array-index assignments and42 authored supplementary symbols are
recorded by Distribution/Assets/SystemFonts/PROVENANCE.json. Matching original
notices accompany every image. No full Unicode/shaping/Bidi coverage is claimed.
Current evidence and actual software/KVM4 limits: Core/FontImport08540.txt/.json.
