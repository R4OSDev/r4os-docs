R4X application model
=====================

R4X is the executable program kind of R4OS. A current R4X file is an R4M0
container with code, data, imports, exports, metadata and optional resources.
The formal container and manifest contracts are owned by
`Repositories/Contract/`.

Startup
-------

Every program exports `R4XStart:1` and imports `R4SYS:Query:1`. Additional
platform groups are declared in `module.R4MF`. Independent Runtime-R4Ls are
imported by module name, table name and minimum revision. The loader resolves
all required imports before entering the program.

The Zig and C SDK startup code validates the context and exposes typed
facades. Optional table fields must be checked with `hasFn`; missing groups
or fields remain explicit errors.

Ownership
---------

Programs own their heap objects, resources, tasks, threads and open handles.
The kernel keeps stable, generation-checked identities and performs ordered
cleanup on normal exit or termination. Application code must not retain
borrowed buffers beyond the operation that supplied them.

Console and GUI programs use the same R4X container. Their app class,
entry mode and image placement are manifest properties rather than separate
binary formats.
