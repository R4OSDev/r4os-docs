R4CODE Desktop-OK 0.51.51
=========================

0.51.51 fuehrt den ersten nativen C-GUI-Pfad fuer inside-R4OS-Projekte ein.
Das Zielprofil heisst:

  R4X_C_Desktop_OK

Es erzeugt ein R4XStart-R4X mit GUI-AppClass und diesen R4L-Imports:

  R4SYS:Query:1
  R4DESK:Query:1
  R4DRAW:Query:1

Der Pfad nutzt keine Kernel-Sonderlogik, keine ProgramApi/API1-Route, keine
Host-IDE und keinen Host-Compiler.


SDK-C-Bindings
--------------

Die C-Header liegen im installierten SDK unter:

  C:\R4OS\SDK\Include\C\r4os\

Neu fuer diesen Schritt sind:

  r4desk.h
  r4draw.h

`r4os.h` bindet diese Header ein. C-Programme erhalten damit kleine Wrapper
fuer den stabilen R4XStart/R4L-Vertrag:

  r4desk_init
  r4desk_program_window_id
  r4desk_gui_set_title
  r4desk_gui_poll_event
  r4draw_gui_clear
  r4draw_gui_rect
  r4draw_gui_draw_text
  r4draw_gui_present
  r4sys_program_should_close
  r4sys_sleep_ticks

Die ABI-Wahrheit bleibt die R4XStart-Tabelle. Die Header sind nur die C-API.


Template
--------

Das SDK-Template liegt unter:

  C:\R4OS\SDK\Templates\R4OS\R4X_C_Desktop_OK\

Es erzeugt:

  HELLOGUI.R4CP
  src\main.c

Die Anwendung setzt einen Fenstertitel, zeichnet Text und einen `OK`-Button
ueber R4DRAW und beendet sich sauber, wenn:

- R4DESK ein Close-Event liefert
- der Benutzer den OK-Button loslaesst
- R4SYS `program_should_close` meldet


Build
-----

R4BUILD erkennt `R4X_C_Desktop_OK` als eigenes Profil. Der Ablauf ist:

1. `.R4CP` lesen.
2. SDK, Buildprofil, Quellen, Imports und Export pruefen.
3. R4CC mit Profil `R4X_C_Desktop_OK-v1` anwenden.
4. R4PACK-Core mit GUI-AppClass und drei Imports anwenden.
5. Artefakt nach `out\<Name>.R4X` schreiben.

Wichtige Loganker:

  R4CC profile: R4X_C_Desktop_OK-v1
  import: R4DESK:Query:1 from build profile
  import: R4DRAW:Query:1 from build profile
  metadata: r4x.class=gui
  R4PACK package: OK
  build result: OK


Abnahme
-------

Der automatische Testlauf baut `C:\TEMP\R4BUILD\HELLOGUI\out\HELLOGUI.R4X`
aus der Projektquelle und inspiziert das Artefakt mit R4PACK. Erwartet ist:

  kind=r4x
  imports=3
  r4x.class=gui
  r4x.start=r4xstart
  r4x.entry=R4XStart

Der sichtbare GUI-Test ist ein Desktop-Test: Das Programm wird als gehostete
GUI-App gestartet und zeigt ein Fenster mit Text und `OK`-Button. Ein Klick
auf `OK` beendet das Programm ueber die normale R4DESK/R4SYS-Ereignisroute.
