R4OS Roadmap
============
*** Version 0.3 ***
Topic: Mauszeiger und Notepad
Status: erledigt

Grundidee:
- kein Desktop-System
- kein Fenstermanager
- keine Maus in der Shell
- Vollbild-App-Modus wie bei klassischen DOS-Anwendungen
- Shell startet NOTEPAD.R4X
- Notepad übernimmt den ganzen Bildschirm
- Quit kehrt zur Shell zurück

0.3.1: Maus-Grundlage
---------------------

Ziele:
- PS/2-Maus initialisieren
- IRQ12 behandeln
- Mauspakete dekodieren
- relative Bewegung in Bildschirmkoordinaten umsetzen
- Mausposition an Bildschirmrändern begrenzen
- linke/rechte/mittlere Taste erfassen
- Mauszustand zentral im Kernel halten
- Mauszeiger zeichnen, ohne den darunterliegenden Bildschirminhalt dauerhaft
  zu zerstören
- Maus nur für Anwendungen vorbereiten, nicht für die Shell

Abnahme:
- Mausbewegungen werden in QEMU erkannt
- Mauszeiger bewegt sich sichtbar über den Bildschirm
- Mauszeiger bleibt innerhalb des Framebuffers
- Klickzustände werden intern korrekt erkannt
- Shell bleibt ohne Mausbedienung normal nutzbar

Aktueller Test:
- MOUSE.R4X startet als Vollbild-Testanwendung
- Q oder ESC beendet MOUSE.R4X
- Mouse IRQ wird in QEMU erkannt


0.3.2: R4X-App-API für Vollbild-Anwendungen
-------------------------------------------

Ziele:
- R4X-API um einfache Grafik-/UI-Funktionen erweitern
- Bildschirmgröße abfragen
- Bildschirm oder App-Fläche löschen
- Rechtecke zeichnen
- Text an Position zeichnen
- Mauszustand aus R4X lesen
- Tastatureingabe weiter aus R4X lesen
- App kann den Vollbildmodus übernehmen und beim Beenden zur Shell
  zurückkehren
- keine Fenster, kein Desktop, keine App-Überlappung

Abnahme:
- ein R4X-Testprogramm kann den Bildschirm löschen
- ein R4X-Testprogramm kann Text und Rechtecke an festen Positionen zeichnen
- ein R4X-Testprogramm kann Mausposition und Buttons auslesen
- nach Ende des R4X-Programms ist die Shell wieder bedienbar
- Shell selbst zeigt keinen dauerhaften Mauszeiger

Aktueller Test:
- MOUSE.R4X nutzt clear/text/mouse_show/mouse_hide
- NOTEPAD.R4X nutzt Vollbild-Grafik, Maus und Tastatur


0.3.3: NOTEPAD.R4X Grundgerüst
------------------------------

Ziele:
- Software/Notepad anlegen
- NOTEPAD.R4X bauen und nach C:\BIN kopieren
- Notepad als Vollbild-App starten
- Bildschirm im Notepad-Stil zeichnen
- Menüzeile oben zeichnen
- klickbares Menü "File"
- Dropdown mit "New", "Open", "Save", "Save As", "Quit"
- Quit beendet Notepad und kehrt zur Shell zurück
- Maus-Hit-Testing für Menü und Dropdown
- Tastaturfokus für Textbereich vorbereiten

Abnahme:
- Shell kann NOTEPAD starten
- Notepad übernimmt den gesamten Bildschirm
- Mauszeiger ist in Notepad sichtbar
- Klick auf "File" öffnet Dropdown
- Dropdown zeigt New, Open, Save, Save As, Quit
- Klick auf Quit beendet Notepad sauber
- nach Quit erscheint wieder der Shell-Prompt

Aktueller Test:
- NOTEPAD.R4X ist im Image unter C:\BIN\NOTEPAD.R4X
- File-Dropdown und Quit sind implementiert
- Q oder ESC beendet Notepad ebenfalls


0.3.4: Textbearbeitung
----------------------

Ziele:
- einfacher Textbuffer im Notepad
- normale ASCII-Zeichen eingeben
- Enter unterstützen
- Backspace unterstützen
- sichtbare Cursorposition im Textbereich
- New leert den Textbuffer
- Dirty-State vorbereiten, wenn Text geändert wurde
- bewusst klein halten: kein Copy/Paste, keine Markierung, kein Desktop-
  Clipboard

Abnahme:
- Text kann im Notepad eingegeben werden
- Enter erzeugt neue Zeilen
- Backspace löscht Zeichen
- Cursor bewegt sich sichtbar im Textbereich
- File -> New leert den Inhalt
- Notepad bleibt nach mehreren Eingaben bedienbar

Aktueller Test:
- NOTEPAD.R4X hat einen einfachen 512-Byte-Textbuffer
- ASCII-Eingabe, Enter und Backspace sind implementiert
- File -> New leert den Textbuffer


0.3.5: Einfaches Speichern und Öffnen
-------------------------------------

Ziele:
- R4X-API um einfache Dateioperationen erweitern, soweit nötig
- Datei aus Notepad speichern
- Datei aus Notepad öffnen
- vorerst einfacher fester Standardpfad erlaubt, z.B. C:\NOTES\NOTE.TXT
- nötige Verzeichnisse im Image oder zur Laufzeit bereitstellen
- Save schreibt Textbuffer nach FAT32
- Open liest Textdatei in den Textbuffer

Abnahme:
- File -> Save schreibt eine Textdatei
- File -> Open lädt eine gespeicherte Textdatei
- gespeicherter Text bleibt nach Neustart im FAT32-Image lesbar
- Fehler wie "Datei nicht gefunden" werden sichtbar gemeldet
- Shell und FAT32 bleiben nach Save/Open stabil

Aktueller Test:
- R4X-API hat file_read und file_write
- R4X-API hat dir_list und dir_entry fuer einfache Verzeichnislisten
- NOTEPAD.R4X nutzt vorerst festen Pfad C:\NOTE.TXT
- File -> Save schreibt den Textbuffer
- File -> Open lädt C:\NOTE.TXT, wenn vorhanden
- Save/Open/Open failed zeigen einfache Statusmeldungen
- R4X-Loader nutzt keinen festen Programmpuffer mehr; Programmdateien muessen
  nur in den verfuegbaren Heap passen


0.3.6: File-Dialog-Prototyp
---------------------------

Ziele:
- einfacher Vollbild- oder Panel-Dialog innerhalb von Notepad
- aktuelles Laufwerk/Verzeichnis anzeigen
- Verzeichniseinträge listen
- Ordner und Dateien unterscheiden
- per Maus Eintrag auswählen
- in Unterordner wechseln
- mit ".." nach oben wechseln
- Datei für Open auswählen
- Dateiname für Save eingeben oder vorhandenen Namen auswählen
- bewusst noch kein vollwertiger Desktop-Dateidialog

Abnahme:
- File -> Open öffnet einen einfachen Dateidialog-Prototyp
- der Dialog kann C:\ anzeigen
- Ordner und Dateien werden unterscheidbar dargestellt
- Klick auf eine Datei wählt sie aus
- Klick auf einen Ordner wechselt in den Ordner
- Klick auf ".." wechselt eine Ebene nach oben
- OK im Dialog lädt die aktuelle Dateiauswahl
- File -> Save schreibt in die aktuelle Dateiauswahl
- File -> Save As oeffnet den Dialog und speichert mit OK in den Selected-Pfad
- der Selected-Pfad kann per Tastatur bearbeitet werden
- Cancel aus dem Dialog kehrt zuverlässig zum Notepad zurück
- Quit/Cancel aus dem Dialog kehrt zuverlässig zum Notepad zurück

Aktueller Test:
- R4X-API dir_list liefert FAT32-Verzeichnislisten
- R4X-API dir_entry liefert eine anklickbare Auswahl
- File -> Open zeigt einen Panel-Dialog mit C:\-Liste
- <DIR>-Einträge werden sichtbar unterschieden
- Datei-Klick setzt die aktuelle Auswahl
- Ordner-Klick lädt die Verzeichnisliste des Ordners
- ".." lädt die Verzeichnisliste des Elternordners
- OK lädt die aktuelle Auswahl, Cancel schließt den Dialog
- Save nutzt die aktuelle Auswahl als Zielpfad
- Save As nutzt den Dialog fuer einen frei editierbaren Zielpfad
- Backspace und ASCII-Zeichen bearbeiten den Selected-Pfad im Dialog


0.3 Abschlusskriterien
----------------------

Abnahme:
- Mausintegration funktioniert für Vollbild-R4X-Anwendungen
- NOTEPAD.R4X läuft als externe Anwendung unter Software/Notepad
- Notepad übernimmt den Bildschirm und gibt ihn bei Quit zurück
- Menü "File" mit New, Open, Save, Save As, Quit ist klickbar
- Text kann geschrieben, neu angelegt, gespeichert und geöffnet werden
- einfacher File-Dialog erlaubt Navigation im Dateisystem
- keine Desktop-/Fenster-Infrastruktur wurde eingeführt
- Shell bleibt nach Notepad stabil nutzbar


*** Version 0.2 ***
Topic: Programme außerhalb des Kernels
Status: erledigt

Ziele:
- eigenes natives Programmformat .r4x definieren
- .r4x-Header mit Magic, Version, Architektur, Entry-Offset, Code-/Data-/
  BSS-Groessen, Stack-Groesse und Flags festlegen
- einfachen .r4x-Loader im Kernel bauen
- Programme von FAT32 laden, zuerst von C:\BIN und optional aus dem aktuellen
  Verzeichnis
- unbekannte Shell-Kommandos als Programmstart versuchen
- Programm als eigenen Task starten
- trusted Ausfuehrung ohne User-/Permission-Isolation
- minimale R4OS-Programm-API bereitstellen, z.B. print, read-key, exit und
  spaeter Datei-I/O
- Argumentuebergabe an Programme vorbereiten
- erstes Beispielprogramm HELLO.R4X ins Image aufnehmen
- Host-Tool oder Build-Schritt vorbereiten, der einfache Testprogramme nach
  .r4x verpackt
- R4X so dokumentieren, dass spaeter Compiler dafuer erzeugen koennen
- langfristige Compiler-Ziele beruecksichtigen: C -> R4X, Zig -> R4X und
  spaeter BASIC -> R4X
- DOS-Programme noch nicht nativ konvertieren, aber das Format so halten,
  dass spaeter DOS-Emulator/Packager daneben existieren kann

Abnahme:
- C:\BIN existiert im Boot-Image
- HELLO.R4X liegt auf der FAT32-Bootdisk
- Shell kann HELLO oder HELLO.R4X starten
- HELLO.R4X gibt Text auf der R4OS-Konsole aus und kehrt zur Shell zurueck
- Programmstart zerstoert den Prompt nicht und endet sauber mit Exit-Code
- fehlerhafte oder unbekannte .r4x-Dateien werden sauber abgelehnt
- ein Programm laeuft als eigener Task oder klar abgegrenzter Programmlauf
- die minimale R4OS-Programm-API ist dokumentiert
- das .r4x-Dateiformat ist in Docs/ dokumentiert
- ein externes Tool oder Build-Schritt kann mindestens ein Testprogramm in
  .r4x erzeugen

====================================================================
Das Fundament der Software wurde nach einem Phasensystem aufgebaut.
Hier die alten abgeschlossenen Phasen:

Phase 1: Boot-Basis
-------------------

Status: erledigt

Ziele:
- Kernel via Limine booten
- x86_64 Long Mode erreichen
- Serial-Ausgabe ueber COM1
- Higher-Half-Kernel bei 0xffffffff80000000

Abnahme:
- QEMU bootet r4os.elf via Limine
- Serial zeigt fruehe Kernelmeldungen
- BuildAndRun.bat erzeugt ein bootbares Image


Phase 2: Bildschirmausgabe
--------------------------

Status: erledigt

Ziele:
- Limine-Framebuffer verwenden
- 8x8-Bitmap-Font rendern
- einfache Textkonsole mit Cursor, Farben und Scrolling
- kprint auf Serial und optional Konsole spiegeln

Abnahme:
- Kernel zeigt Bootstatus im QEMU-Fenster
- Ausgabe bleibt auch ohne Konsole ueber Serial sichtbar
- Console scrollt korrekt


Phase 3: CPU-Grundlagen
-----------------------

Status: erledigt

Ziele:
- GDT sauber aufsetzen
- TSS fuer Kernel-Stacks vorbereiten
- IDT aufbauen
- Exception-Handler fuer CPU-Faults
- einfache Panic-Ausgabe mit Registerdump
- Interrupts kontrolliert aktivieren/deaktivieren

Abnahme:
- absichtlich ausgeloeste Exceptions landen im Handler
- Panic zeigt Fault-Nummer, RIP, RSP, CR2 bei Page Fault
- Triple-Faults werden fuer bekannte Fehlerpfade vermieden


Phase 4: Speicherverwaltung
---------------------------

Status: erledigt

Ziele:
- Limine-Memory-Map auslesen
- physischer Frame-Allocator
- Kernel-Heap
- Paging-Strukturen kontrolliert verwalten
- Mapping/Unmapping-Hilfen
- Page-Fault-Handler

Abnahme:
- freie/benutzte Speicherbereiche werden korrekt geloggt
- Frames koennen alloziert und freigegeben werden
- Kernel-Heap funktioniert fuer kleine und mittlere Allokationen
- Page Faults werden sichtbar diagnostiziert


Phase 5: Zeit und Interrupts
----------------------------

Status: erledigt

Ziele:
- PIC fuer die aktuelle x86_64-QEMU-Basis verwenden
- Timer initialisieren
- IRQ-Dispatching
- Tastatur-Interrupt als erster echter IRQ-Treiber
- einfache monotone Tick-/Zeitbasis

Abnahme:
- Timer tickt reproduzierbar
- Tastaturereignisse kommen ueber IRQ an
- Kernel kann zwischen Busy-Wait und Timer-basiertem Warten unterscheiden


Phase 6: Tasks, Scheduler und Kernel-API
----------------------------------------

Status: erledigt

Ziele:
- Task-/Thread-Struktur
- Kontextwechsel
- einfacher Round-Robin-Scheduler
- Kernel-Stacks pro Task
- Kernel-API oder Syscall-Schicht definieren
- einfacher Task-Lifecycle mit Exit/Kill/Alive-Abfrage

Abnahme:
- mehrere Kernel-Tasks laufen abwechselnd
- ein Task kann schlafen/yielden
- ein Task kann sich sauber beenden
- Kernel-API ist stabil genug fuer erste Services


Phase 7: Dateisystem und Storage
--------------------------------

Status: erledigt

Ziele:
- Blockdevice-Abstraktion
- ATA/IDE-Read-Sectors fuer QEMU-Bootdisk
- MBR-Partitionstabelle lesen
- FAT32-Disk-Image-Erzeugung im ImageCreator
- FAT32 lesen
- FAT32 schreiben
- FAT32-Pfadaufloesung fuer Dateien und Verzeichnisse
- DOS-artiges Laufwerksmodell mit Prompts wie X:\> und C:\>
- RAM Drive X: beim Boot bereitstellen
- interaktive DOS-artige Eingabeschleife
- C64-artiger Bootscreen ohne sichtbaren Debug-Log
- Dateien oeffnen/lesen/listen
- DOS-Befehle DIR, CD, TYPE, COPY, DEL, MD, RD, WRITE
- Dateien schreiben, ersetzen und loeschen
- Verzeichnisse anlegen/listen/loeschen
- Boot-Image-Inhalte aus dem laufenden System lesen

Abnahme:
- X:\> erscheint nach dem Boot als Startprompt
- Prompt bleibt interaktiv und faellt nicht direkt in den Halt-Loop
- Bildschirm zeigt nach dem Boot nur R4OS-Startscreen, READY und Prompt
- Boot-Disk kann als Blockdevice gelesen werden
- MBR-Partitionen werden erkannt und geloggt
- Boot-Image ist FAT32 und bleibt via Limine bootbar
- FAT32-Root-Directory wird gelistet
- DIR und CD erlauben Navigation im FAT32-Dateisystem
- TYPE kann Dateien aus FAT32 anzeigen
- Dateien koennen neu geschrieben, ersetzt, kopiert und geloescht werden
- Verzeichnisse koennen angelegt und geloescht werden
- Fehler werden sauber gemeldet statt den Kernel zu zerlegen


R4OS Changelog V0.3.7
=====================

Thema
-----

Mauszeiger und DOS-artige Vollbild-R4X-Anwendungen.


Umgesetzt
---------

- PS/2-Maus initialisiert und IRQ12 verarbeitet.
- Mauspakete werden dekodiert; Position, Bewegung und Tastenstatus werden im
  Kernel gehalten.
- Mauszeiger bleibt innerhalb des Framebuffers und ist fuer Vollbild-Apps
  nutzbar.
- R4X-App-API erweitert um Bildschirmgroesse, Clear, Rechtecke, Textausgabe,
  Mauszustand, mouse_show und mouse_hide.
- R4X-Datei-API erweitert um file_read, file_write, dir_list und dir_entry.
- MOUSE.R4X als Vollbildtest fuer Maus, Grafik und Tastatur eingebunden.
- NOTEPAD.R4X unter Software/Notepad als externe Vollbild-App angelegt.
- NOTEPAD.R4X zeichnet Menueleiste, File-Dropdown und Textbereich.
- File-Menue enthaelt New, Open, Save, Save As und Quit.
- Textbearbeitung unterstuetzt ASCII-Eingabe, Enter, Backspace, sichtbaren
  Cursor und New.
- Save und Open lesen/schreiben Textdateien ueber die FAT32-R4X-API.
- Ein einfacher Dateidialog zeigt C:\, unterscheidet Dateien und Ordner,
  erlaubt Ordnerwechsel, "..", Dateiauswahl, OK und Cancel.
- Save As nutzt den Dateidialog und erlaubt das Bearbeiten des Selected-Pfads
  per Tastatur.
- R4X-Loader nutzt kein festes Programmgroessenlimit mehr. Programmdateien und
  Stacks muessen nur in den verfuegbaren Kernel-Heap passen.
- Nach Vollbild-R4X-Anwendungen zeichnet die Shell Rahmen und Prompt neu, wenn
  die App Grafik oder Maus verwendet hat.


Abnahme
-------

- MOUSE.R4X erkennt Mausbewegung und Klickstatus in QEMU.
- NOTEPAD.R4X kann aus der Shell gestartet und per Quit, Q oder ESC beendet
  werden.
- Nach dem Beenden von NOTEPAD.R4X erscheint die Shell wieder sauber.
- Notepad kann Text schreiben, neu anlegen, speichern und wieder oeffnen.
- File -> Open und File -> Save As zeigen den Dateidialog mit echter
  FAT32-Verzeichnisliste.
- Es wurde keine Desktop- oder Fenster-Infrastruktur eingefuehrt.
