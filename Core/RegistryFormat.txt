R4R1 registry format
====================

R4R1 is the binary, little-endian format of an R4OS registry hive. A file
contains a header followed by fixed-layout key and value records, a string
pool and a data pool. Indices and offsets are validated before a view is
published.

The format supports a rooted key tree and typed values. Names are stored once
in the string pool; value payloads reference bounded bytes in the data pool.
Unknown versions, duplicate or cyclic ownership, invalid parent/child links,
out-of-range offsets and inconsistent counts are rejected.

The implementation truth is the shared parser/builder in
`Repositories/SDK/r4os/registry_core.zig` together with the kernel consumer.
This document intentionally does not duplicate numeric structure sizes.
Writers build a complete new image, re-open it with the same validator and
then commit it atomically as SYSTEM.TMP/SYSTEM.BAK/SYSTEM.R4R. The validated
view and its bytes remain one immutable in-memory generation. A writer builds
in the inactive slot and publishes that slot only after byte-exact TMP and
installed-target verification; readers can therefore observe the complete old
or complete new generation, never an in-progress reconstruction.
