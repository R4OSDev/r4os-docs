App-Projektstruktur 0.51.19
===========================

Ziel
----

0.51.19 migriert die Netzwerktools und R4X-Services auf die eigenstaendige
SDK-Projektstruktur. Diese Stufe ist empfindlicher als 0.51.18, weil Services
ueber `SERVICES.R4S`, Autostart und Service-Endpunkte gefunden werden. Die
Runtime-Pfade bleiben deshalb gleich, waehrend die Quellprojekte eigene
Build-Einstiege und Manifeste bekommen.


Migrierte Netzwerktools
-----------------------

Terminal:
- Dhcp -> DHCP.R4X
- DnsLookup -> DNSLOOKUP.R4X
- HttpGet -> HTTPGET.R4X
- IpConfig -> IPCONFIG.R4X
- NetCat -> NETCAT.R4X
- Ping -> PING.R4X
- Recv -> RECV.R4X
- Send -> SEND.R4X
- TcpEcho -> TCPECHO.R4X

Desktop:
- NetConfig -> NETCFG.R4X

NetConf ist kein produktives Quellprojekt. Im Repository gab es nur einen
leeren Platzhalter ohne `main.zig` und ohne Build-Eintrag. 0.51.19 erzeugt
deshalb keine Dummy-App; die echte Netzwerk-Konfigurationsanwendung ist
`Code/Software/NetConfig` mit dem Artefakt `NETCFG.R4X`.


Migrierte Services
------------------

- AudioService -> AUDSVC.R4X
- ClipboardService -> CLIPSVC.R4X
- DhcpService -> DHCPSVC.R4X
- DnsService -> DNSSVC.R4X
- ExampleService -> EXSVC.R4X
- LogService -> LOGSVC.R4X
- SerialLinkService -> R4SLSVC.R4X
- TcpService -> TCPSVC.R4X
- TimeService -> TIMESVC.R4X
- UdpService -> UDPSVC.R4X
- WindowService -> WINSVC.R4X

Alle Services bleiben unter `C:\R4OS\SERVICES\*.R4X` erreichbar. Die
bestehende `Injection/R4OS/CONFIG/SERVICES.R4S` bleibt der sichtbare
Autostart- und Service-Manager-Vertrag.


Manifest-Erweiterung
--------------------

`module.R4MF` darf seit 0.51.19 zusaetzlich `META=`-Zeilen enthalten. Der
Image-Sammler liest und zaehlt diese Zeilen, nutzt sie aber nicht als eigene
Image-Regel. Damit koennen IDE, SDK oder Inspector spaeter Service-Metadaten
sehen, ohne dass das Image-Format oder `SERVICES.R4S` dupliziert wird.

Beispiel:

    META=app.class=service
    META=service.name=CLIPSVC
    META=service.args=/RUN
    META=service.start=auto
    META=service.enabled=yes
    META=service.config=Injection\R4OS\CONFIG\SERVICES.R4S

Wichtig: `module.R4MF` beschreibt das Modul und seinen Build-/Deploy-Vertrag.
`SERVICES.R4S` bleibt die laufende Service-Konfiguration im Systemimage.


Imports
-------

Jedes Projektmanifest nennt `IMPORT=R4SYS:Query:1`, weil R4XStart-Programme
den Start- und Basissystempfad darueber erhalten. Fachliche Abhaengigkeiten
werden explizit ergaenzt:

- Netzwerktools und Netzwerkservices: `R4NET:Query:1`
- NETCFG: `R4DESK`, `R4DRAW`, `R4NET`, `R4DEV`
- AUDSVC: `R4AUDIO:Query:1`
- TIMESVC: `R4STD:Query:1`

Services brauchen keinen eigenen SDK-Komfortlayer fuer den ersten Schnitt.
`sdk.addR4XService` setzt die App-Klasse auf `service`; die Service-Logik
nutzt weiterhin R4XStart plus R4SYS und bei Bedarf R4NET, R4AUDIO oder R4STD.
