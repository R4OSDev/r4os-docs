R4OS update workflow
====================

Components
----------

- UPDSVC searches the configured package server, downloads packages and owns
  the single durable update job.
- UPDATE.R4X is the graphical frontend.
- SYSUPD.R4X is the administrative verification, apply, resume and status
  frontend.
- The shared update engine owns package parsing, staging, journal, rollback,
  inventory and post-boot completion.

Search and download never install by themselves. The service validates the
catalog schema, immutable filename, size and SHA-256 before handing a package
to the common engine. All frontends observe the same job and cancellation
state; they do not implement parallel installers.

Install flow
------------

1. Verify package structure, identities, requirements, targets and checksums.
2. Stage every payload on the target volume.
3. Persist a journal and revalidate the staged bytes.
4. Commit live-safe applications or bind restart-required packages into one
   restart batch.
5. On the next boot, recover or finish every pending transaction.
6. Advance the release only after running and installed components match the
   release manifest for the local image profile.

Interrupted uploads and downloads use explicit temporary ownership and
compare-and-delete cleanup. A foreign file is never removed merely because it
uses the same name.
