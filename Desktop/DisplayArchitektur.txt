R4OS display architecture
=========================

Layers
------

- Boot display: early and fatal output on the Limine framebuffer.
- Display manager: active backend, geometry and presentation.
- Software surfaces: validated XRGB32 pixel storage.
- R4DRAW: public drawing, font, image, surface and frame operations.
- R4DESK: windows, events, desktop state and remote-frame access.
- Desktop R4X: composition, policy and visible user interaction.

Applications draw through R4DRAW into their assigned targets. The desktop
owns window placement, clipping, damage, z-order and final presentation.
Early boot output remains separate and is invalidated when the normal
desktop takes ownership.

Software surfaces use XRGB32. Width, height, pitch, clipping and source/
destination rectangles are validated before pixels are published. Remote
desktop services consume completed frames through R4DESK and return input
through the same contract; they are not a second display owner.
