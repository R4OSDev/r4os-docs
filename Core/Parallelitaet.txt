---------------------------------------------------------------------
Release0.87.51 / Kernel0.1.410 / Spectra0.1.78. Driver Work und Scheduler
bleiben Kernelbesitzer: Die Auswahl einer Kernelcontinuation braucht dessen

kein Thread und kein neuer oeffentlicher Contract/SDK-Import.

generiertes Ticket, Modulowner/Geraetekennung, Frist und Originalbudget.

ein laufender Callback behaelt sein eigenes Ticket/Start/Budget, auch wenn
eine fruehere weitere Arbeit eintrifft. Ownercleanup/Unload verwendet diese
gleichen Cancel-/Finishrouten; Release bleibt nach echter terminaler Quittung.

und unter bereits vorhandener Scheduler-Runtime gelesen. Ein einziger

0.87.39: bounded cooldown exception for a confirmed idle allowed core
---------------------------------------------------------------------
Release0.87.39 / Kernel0.1.402, SPEED-037 (Medium). Normal migration cooldown
remains30ms. One shared native task/migration owner now admits an early move
only for Interactive or ShortCompletion work, with another real task competing
on its prior CPU and a confirmed entirely idle allowed destination core.
Interactive is the canonical normal, unmetered role (boost counters0/0);
ShortCompletion additionally needs both remaining boost ticks and dispatches.
Neither role is promoted and migration never replenishes those budgets.
An independent per-Task last-exception timestamp limits each role to one early
exception per30ms. A normal/policy move or role change does not clear that cap.
The cap is consumed only when an actual different destination is committed.

The target must belong to the current hard CPU set and a known topology core.
Every confirmed member of that core must still be schedulable, have an actual
physical idle current and an empty Ready queue. An unknown/partially offline
core, busy SMT sibling or physically departing non-idle stack is insufficient.
The source check excludes the candidate itself; topology/cache/rank preference
alone never opens this exception. Ordinary post-cooldown placement is retained.

Wake home selection and bounded Ready transfer use these same facts/policy.
The singleton shortcut may reject a bound/unsafe task or unavailable budget,
but must leave a possible exception for the existing bounded target search.
Current-task exclusion, saved RSP/FPU image, exact owner/lifetime, preempt depth,
held Mutex, guard-offer/handoff, wait/timeout and CPU-mask barriers are unchanged.
Ready order/time, role/donation budget and fairness remain at their native
owners. The Task-local extra timestamp is not a second identity/lifetime table;
public ABI/module contracts remain unchanged. No additional global admission,
worker, background scan or CPU-capacity limit is introduced.

The pure actual policy passes four host cases: alternating competing cores
cannot replenish the rate cap; exhausted boost/invalid time cannot grant it;
the unmetered normal Interactive role still has the migration cap; and unknown,
partial or busy SMT cores fail physical-idle admission, including siblings
outside the candidate's hard set. Existing real placement cases are extended
with two producer modes: a real initial migration, short blocking/wake, one
exception and a further wake with the exception budget already consumed.
Each suspends/resumes a full YMM vector and the exact task-bound unwind token.
The existing YMM store helper executes vzeroupper, so each new wait reloads its
full test vector; this is a test precondition, not a new FPU production fix.
Busy peers are actual owned Input tasks on their actual CPUs. They are released
at the bounded control cutoff and retired through the existing ledger; no
foreign queue/load/frame is rewritten to manufacture an idle target.

Program and bound Runtime-R4L code are preemptible; kernel code uses explicit

Rules
-----

- IRQ handlers perform bounded work and defer longer operations.
- A lock is not held across I/O, yield, wait or application callback.
- Wake producers publish state before signalling the matching wait queue.
- Completion at a timeout boundary wins when it can be proven.
- Desktop and drawing objects are owner-thread-only unless the API explicitly
  states otherwise.
- Service reactors process only short nonblocking requests; session work uses
  bounded workers or explicit asynchronous completion.

Module code may use SIMD. The scheduler saves a CPUID/XCR0-sized FPU state
for every executable task, including kernel-main and generic kernel workers:
storage, networking, IPC and graphics work can enter R4D/R4P callbacks even
though the kernel itself uses the checked Rust release profile without SIMD.
Only the dedicated CPU-idle task, which cannot enter modules, skips this state.
The external R4D IRQ guard saves that same task state before installing a
clean handler state, then restores it on return. The standard module target
assumes AVX2. A kernel-worker label is not evidence of a SIMD-free call graph.
The canonical initial image resets XMM/YMM and MXCSR to0x1F80 explicitly;
FNINIT alone only resets x87 and can retain the firmware's SIMD contents and
rounding/exception policy. AP and IRQ initialization reuse the same image.

The four critical Task/stack reserve bundles also preallocate their FPU
buffers at boot. Admission under memory pressure performs no new allocation;
retirement retains the buffer and the next admission resets its register
image. OPTION TASKREGISTRY selftest=fpu-work selects the bounded existing
Task test for both shared Driver Work lanes, kernel-main and two reserve
reuses across the real IRQ FPU boundary. It does not execute GPU commands.

SMP ownership foundation
------------------------

The x86_64 SMP foundation admits at most64 logical CPUs. One shared capacity
binds firmware selection, AP startup, CPU-local state, GDT/TSS/IST, clock
corrections, scheduler queues and TLB acknowledgements. Whole MADT chains
up to1MB are inspected: disabled and duplicate records consume no slots,
full32-bit APIC IDs are retained and excess eligible records are counted.
A malformed chain falls back to the BSP. UID aliases are checked across the
whole list, including omitted records. CPU masks retain bit63; the private
128-slot stream pool uses128-bit per-volume retirement masks under its
existing owner. Configured dense slots remain distinct from qualified,
failed, online and schedulable CPUs. Public indexed records and CPU word
vectors keep their layouts. Structural64/128 tests and real KVM-SMP4 results
are separate; native>32 remains unqualified. Core/CpuCapacity08522.txt/.json
holds the evidence. The BSP starts
each AP sequentially through a private low-memory INIT/SIPI trampoline and a
bounded wait. An AP becomes schedulable only after its CPU-local GDT, TSS,
GS base, FPU state, IDT, LAPIC and scheduler idle state are complete. Missing,
duplicate, disabled or failed APs stay outside the schedulable mask and never
prevent the BSP from continuing; one CPU is a permanent supported mode.

CPU-local state is one cache-line-sized `CpuLocal` record addressed through
GS. It owns the CPU index and APIC ID, lifecycle state, scheduler readiness,
runtime-critical depth and productive-work state. Current/idle task, Ready
queue and reschedule request are also per CPU. Initial placement chooses the
least-loaded online CPU. Since 0.84.27, an empty Ready queue can take one
audited SMP-eligible non-running task from a queue with at least two Ready
tasks. A bounded rotating donor/candidate search and one-quantum cooldown
avoid whole-task scans and immediate repeated moves. Explicit CPU bindings,
driver/async execution owners, tracked locks, handoffs and unsafe lifecycle
states remain excluded. The exact source current task cannot migrate.

Migration stays under the existing runtime owner; ready order/time, role and
priority budgets, exact task/stack/FPU/unwind identities survive. The target
queue, home CPU, pending state and required reschedule IPI publish together.
The unchanged assembly release follows the durable outgoing RSP. One native
fairness extension checks already-started sleepers, pinned refusal, actual
YMM/unwind preservation and exact retirement; original SMP cases still cover
fixed placement/TLB/owner work. Scope and limits: KernelBalance08427.json.

Every AP qualifies its TSC against the shared HPET epoch before becoming
schedulable. Bounded per-CPU corrections feed one common nanosecond
clocksource, and a global monotonic clamp orders concurrent reads. Failed
correlation never discards an otherwise healthy AP: all CPUs switch to the
common HPET fallback. Logical ticks derive from this clocksource, while LAPIC
and HPET continue to own interrupt delivery and idle one-shots.

The ownership matrix is deliberately conservative:

- Per CPU: GDT/TSS/fault stacks, FPU register initialization, LAPIC timer,
  current and idle task, Ready queue, reschedule state and IRQ-dispatch depth.
- Runtime owner: task identity, per-CPU Ready projections, timed waits,
  deferred reap, wait queues and IRQ-side preemption share the one reentrant
  boundary released by the assembly context-switch publication point.
- Explicit no-sleep owner locks: program-thread state (1), independent
  storage/network/driver-work entry owners (2), heap (5), VM (10), page
  tables (20), physical PMM/MemoryBlock state (30), boot log (70) and serial
  output (80). A lower rank may never be acquired while a higher rank is
  held; equal-rank I/O owners do not nest into one another.
- Service registry, endpoints and channel IPC retain their existing
  sleepable, ranked mutexes. Only their scheduler-facing waiter transitions
  briefly enter the runtime owner.
- BSP-only until separately audited: foreground and shell main tasks, modules
  without an audited execution declaration, Desktop and unaudited R4D
  callbacks. Since0.85.15 owned-v1 VM/page-in/reclaim accepts AP callers;
  file operations keep exact buffer/volume/request owners and existing workers.
  Core/ApMemoryIo08515.txt/.json states the remaining backend limits.
  Since0.85.16 reviewed secondary block workers, the cache worker, copied
  RX frames and reviewed native IPC handlers may execute on APs; only NVME
  and VIRTNET declare r4d.parallel_callbacks=owned-v1. Critical primary
  block, per-module R4P and per-channel IPC serialization remain.
  Task-owned nested PPI scopes and lossless completion enrollment are
  documented in Core/KernelWorkers08516.txt/.json.
- Parallel-enabled: explicitly marked kernel work and background R4X with
  runtime.parallel=owned-v1. Current canonical manifests declare this for
  Calculator, CLIPSVC, Spectra, Notepad, Explorer and LogCenter; LSTRX
  remains a separate test fixture.
  Child threads inherit the instance declaration; see the 0.81.19 contract below.

The scheduler runtime owner is reentrant and uses
acquire/release publication. It is a no-sleep boundary: outside bounded IRQ
dispatch, no blocking I/O, wait, yield or external callback may occur while
nested inside it. The responsible IRQ path may acknowledge its device and
perform bounded MMIO or port-register access. A context switch releases its
outer token only after the outgoing RSP is durable, and a remotely woken task
is queued only after its old CPU has physically switched out. This closes the
lost-wake, duplicate-stack and premature-reap windows without inventing a
public lock or affinity contract.

The old class-dispatched `saveAndDisableFor` entrypoint and its global BKL no
longer exist. Runtime users call the runtime owner explicitly; independent
mutable domains call their exact owner, and the USB deadline sampler uses a
purely CPU-local IRQ guard. Telemetry counts acquisitions, nesting, CPU
collisions, total/maximum wait spins and hold cycles without logging
recursively from a lock path. Owner locks additionally count rank violations.
Waiting task-context callers briefly restore interrupt delivery between
failed attempts so the higher-priority TLB IPI remains serviceable.

The short SMP4 acceptance performs 64 allocate/write/free cycles per online
CPU through the real heap owner, including one 512-KB to 2-MB allocation per
CPU for concurrent growth. It requires every CPU witness and rejects any
owner-order, cleanup or content failure. Its lock marker also requires the
retired global-BKL counter to remain zero. The same workers also perform
64 shared mutex-protected increments each; the final count must equal the
number of online CPUs times 64, with no failed acquisition or unlock.

Serial span output
------------------

Kernel `puts` forwards one complete span to the optional COM1 bulk sink.
The serial owner is acquired once, the bytes are appended in order to the
fixed TX ring and at most one nonblocking FIFO drain is attempted. Hooks that
intercept serial output and true single-character writes keep their byte
semantics. Poweroff and crash paths retain bounded synchronous draining.
Counters expose span calls, bulk calls, owner acquisitions, UART status
reads, maximum span and dropped bytes; the short SMP4 contract requires zero
drops and fewer status reads than emitted ring bytes.

Cross-CPU TLB coherence
-----------------------

R4OS currently uses one shared active kernel address space. Removing a PTE,
clearing hardware-dirty state or changing cache attributes therefore
publishes one generation and address/page-count request, sends vector F2 to
every other online CPU, and waits for a per-CPU acknowledgement of that exact
generation. Small ranges use `invlpg`; ranges of 64 pages or more reload CR3.
CPUs which become offline after the snapshot are excluded explicitly.

An invalidation has a bounded wait. On a missing acknowledgement the paging
owner restores the old PTE values and performs a recovery invalidation; the
caller receives failure and must not release or reuse the physical frame.
VM uncommit holds locks in VM -> page-table -> physical order and frees PMM
state only after a successful acknowledgement set. The short SMP4 acceptance
loads the old translation on all four CPUs, remaps to a distinct frame,
checks the new value everywhere, then drops one acknowledgement deliberately
and proves that unmap fails while the frame and mapping remain owned.

Timer- and reschedule-IPI preemption use the same interrupt-frame decision on
every online CPU. An instruction pointer is preemptible only when it belongs
to the running program image or to an executable section of one of that exact
program generation's bound Runtime-R4Ls. Stale module generations, data
sections and unrelated modules fail closed; kernel instruction pointers defer
the request to an explicit safe boundary. Each AP owns its periodic LAPIC
accounting timer and accepts the common reschedule IPI. PCI INTx and single-
message MSI registrations choose internal online targets after AP activation.
No public CPU-affinity, priority or multi-vector ABI is exposed. Shutdown and
reboot remove APs from scheduling and stop them with a bounded IPI handshake.

Long synchronous loops use cooperative boundaries only where ownership stays
stable across a switch. FAT32 already yields between bounded filesystem work
steps. Runtime-R4L image decoders are covered by executable-range preemption.
GUI frame clones and reads pin an immutable source and may reschedule between
command blocks, 128x128 raster tiles, or 64-KiB copy chunks. No such point is
placed while the frame-state lock is held, inside an unpublished frame splice,
or midway through display publication; those paths must preserve one complete
generation and are optimized at their owning layer instead.

New kernel threads enter their common trampoline through a synthetic context
switch rather than a hardware `call`. Its six saved-register words and one
reserved top word preserve the SysV x86_64 entry rule (RSP modulo 16 equals
8), so a worker may safely call SIMD-capable modules. A build-time layout test
keeps this stack contract synchronized with the assembly restore frame.

Scheduler work sets
-------------------

The stable Task registry owns identity and inventory only. Its intrusive
projections remain under the shared runtime owner: one Ready FIFO per CPU,
four Ready-rank AVL indices, the finite-deadline AVL with its ordered list,
and deferred-reap candidates. Index nodes live inside their stable Task;
mutation never allocates or swaps Task payloads. Rank selection visits at
most four cached heads. Each rank is ordered by original Ready enrollment,
so donation or budget changes preserve the former FIFO tie rule. Since
0.87.29 every eighth successful non-urgent selection of the same CPU uses
that CPU's raw Ready FIFO head in constant time; empty/urgent/foreign
attempts cannot consume its phase. The former global-counter gap is
qualified in the0.87.29 section above.

Ready insertion/removal, rank changes and deadline insertion/removal take
logarithmic index work. Deadline neighbors maintain the existing list;
its cached head still drives timeout dispatch and tickless idle. Equal
deadlines retain enrollment order. Independent 128-bit enrollment serials
remove the former whole-list renumbering at the 64-bit sequence boundary;
64-bit deadline saturation remains unchanged. One timer IRQ or BSP idle
checkpoint wakes at most 64 due tasks, leaving an ordered backlog for the
next check. A reaper
pass visits only the candidates present at its start.

With metrics enabled, every sixteenth tick samples at most eight Ready tasks
per CPU through a rotating cursor. Unlink moves that cursor before a Task can
retire. Starvation warnings may therefore lag by a sweep of the Ready set,
but diagnostics no longer scan the whole list in one IRQ. Held diagnostic
mutex-slot totals are maintained at acquire/release; reading lock metrics
no longer scans the Task registry. These limits bound diagnostic work without
changing dispatch, wake, cancellation or object lifetime.

Active execution retains the periodic scheduler source needed for preemption.
When the current task is truly idle, HPET or the calibrated LAPIC is switched
to a one-shot for the queue head; an empty deadline queue disarms it. An
external wake cancels the pending shot and reevaluates the head. Long deadlines
use bounded hardware checkpoints. PIT systems remain periodic, while logical
ticks, watchdog budgets and runtime accounting continue on the same epoch and
do not count IRQ deliveries as elapsed time.

Before rearming or halting, the BSP processes already expired task deadlines
under the runtime owner through the same bounded timeout wake path. It then
rechecks its Ready queue. A remaining expired backlog prevents sleeping;
future deadlines stay enrolled. This keeps repeated device/IPI wakes from
continually converting a past absolute deadline into another minimum-length
hardware one-shot. The adjacent STI/HLT publication boundary, AP behavior,
clocksource, timer policy and task identity rules remain unchanged. The
existing TASKREGISTRY selftest=idle-deadline selection checks the 64+1 bound,
future-wait preservation and expiry without a new timer IRQ (0.82.44).

The BSP restores periodic delivery whenever a scheduler handoff selects
productive work, when productive work observes a no-op yield, and when the
last idle one-shot IRQ arrives after work has already taken over. Thus a
suspended idle epilogue cannot leave later one-tick waits without an event
source. Publishing a newly constructed AP-bound task also requests a remote
reschedule explicitly; Ready publication alone is insufficient when that AP
is already halted behind its idle deadline.

Kernel owners assign one of four internal scheduler roles: input, short
completion, interactive, or batch. Application/service threads default to
interactive. Since0.85.13 the optional native thread-placement API can request
Interactive, Batch or bounded ShortCompletion within the exact module/CPU
admission; remaining preferred budget survives class reentry. Input remains
an internal role. Priority is the compact diagnostic lane derived from the
role; CPU reservations and hard real-time guarantees are not provided.
API/ThreadPlacement.txt describes the actual optional contract.

Input activations receive 2 run ticks and 4 dispatches of rank-0 budget; short
completions receive 4 and 4 at rank 1. Consuming either bound demotes that
activation to interactive rank 2 until it blocks and is woken again. Batch is
rank 3. Selection takes the first task of the best rank from the Ready FIFO,
while, since0.87.29, every eighth successful non-urgent local selection
takes that CPU's raw FIFO head to preserve
cross-role NORMAL/LOW progress. A contended mutex may donate the waiter's rank
to its owner for at most 4 ticks and 4 dispatches; donation is removed on the
final unlock and cannot create an unbounded high lane.

A contended mutex transfers ownership directly to one selected waiter on its
final unlock. Mutex ID/generation, depth one and the target's canonical held
lock count are published before Ready. The first successful retry acknowledges
this handoff without adding recursion depth. New arrivals cannot steal it.
A hard kill after selection is deferred by the same rule as any other owned
mutex; the task resumes and unlocks normally. Timeout/cancel/kill before
selection removes the wait node. Failed wake publication undoes ownership and
continues to the next candidate. Normal unlock wakes one successor; stale or
inadmissible waiters cannot strand the remaining queue. The role/FIFO search
itself remains linear and is not claimed to be constant-time.

A directed single wake chooses the best enrolled wake role and remains FIFO
inside one rank. Wake-all, cancellation, kill, and retry drains stay strict
FIFO. The producer publishes Ready state and a reschedule request while still
inside its critical section, but generic WaitQueue code never switches there.
IRQ work consumes the request only after all handlers and EOI. Synchronous
service and completion producers may use an explicit safe return point only
after their owner publication and locks are complete; enabled interrupts, zero
preemption depth, zero held locks, and no semaphore handoff are required. Until
then the request remains pending.

Clock fallback and bounded qualification (0.78.34)
------------------------------------------------
A TSC rejected by the watchdog is never sampled again to anchor the fallback.
The last published nanosecond value anchors the new HPET epoch, which then
advances from its newly sampled counter. An ordinary TSC read below the boot
origin keeps the published value until validation; resolving such a stamp
fails instead of converting unsigned wrap into a huge timestamp. HPET stamps
older than the new fallback origin are likewise rejected.

HPET startup requires counter movement within 65536 polling reads, independently
of a CPU frequency or timer interrupt. TSC calibration has at most one million
polling reads per sample and also rejects backwards/incomplete correlations.
A stalled or regressed HPET ends qualification; its enable/legacy bits are
cleared and its usable frequency is zero, so later timer selection cannot use
it. A previously qualified invariant TSC remains active. Otherwise the existing
periodic-clock wrapper remains the available time source. This is a finite
operation bound, not a host-independent duration guarantee for MMIO access.

Platform interrupt routes and ECAM windows (0.78.35)
-------------------------------------------------
Dynamic IOAPIC routes use the same MADT override resolution as the predefined
routes. Redirection indices are GSI minus the controller GSI base; activation
and mask changes therefore affect the requested entry. Only device IRQs 0..31
have corresponding IDT handlers and may be selected by this route interface.
The BSP/AP LAPIC spurious vector is shared with IDT initialization. Its dedicated
assembly entry returns directly with IRETQ, preserving registers and issuing no
EOI because a spurious interrupt has no corresponding in-service request.

An MCFG base always describes bus zero. Configuration addresses include the
absolute bus number; StartBus/EndBus limit coverage. The mapped ECAM aperture
and its readiness checks use Base+(StartBus<<20) and the advertised bus count,
with a common checked geometry helper. They never map the unshifted base for
a nonzero start bus. Partial coverage still uses existing legacy fallback for
the other buses. Multiple MCFG segments/controllers are outside this change.
Hardware semantics were checked against these primary Linux references:
https://www.kernel.org/doc/html/latest/PCI/acpi-info.html
https://raw.githubusercontent.com/torvalds/linux/master/arch/x86/kernel/apic/apic.c
(handle_spurious_interrupt, accessed 2026-09-08; no Linux code imported.)

Bounded cooperative kernel work (0.81.15)
----------------------------------------

The kernel RIP filter remains conservative. Explicit safeReschedulePoint
boundaries also serve equal-rank Ready tasks once the running quantum has
expired; urgent wakes still bypass the quantum. A point first rejects any
outer no-sleep or runtime owner, then checks IF, preemption depth, held
mutexes and pending wait handoff. Resource lifetime is the caller's duty.
An UnwindToken permits suspension while preventing hard kill of an unfinished
transaction; it is not a held owner lock.

Reader-pinned GUI clones/reads already provide boundaries after 64-KB copies,
command blocks and 128x128 raster tiles. Eager VM commit and failed-commit
rollback now use the same boundary after at most 64 pages, with the VM owner
released, the range lease active and the unwind token enrolled. Private
frames and rollback cursors stay owned throughout. Publication sections and
other unaudited kernel loops are not made asynchronously preemptible.

The existing short R4LPREEMPT acceptance includes an equal-rank kernel worker
and ordinary LSTRX on the same AP. The worker processes a private 64-KB buffer
until LSTRX enters; progress requires a successful explicit boundary. The
probe checks normal program completion and buffer cleanup. KERNELCOOP reports
its switches; its success is included in the existing R4LPREEMPT result.

Owner-local cooperation (0.85.14, Kernel0.1.341)
------------------------------------------------
The original VM/GUI points above remain. Storage workers now bound each
per-device pass to8 submission/completion steps and checkpoint only after
actual publication/finish; synchronous read/write chunks cap ordinary copy
work at64KB with exact device pin/unwind. Batch siblings need real receipts.
Pagecache writeback/trim yields only after its owners return. Outer RX batches
checkpoint between settled groups of8 frames and after maintenance; nested
poll processing does not switch under PollGuard. IPC checkpoints cover all
worker outcomes, including abandoned messages. A pending exact thread policy
also reaches the existing full-save switch without another Ready task.
The safe-point counters use separate native atomics outside mutable Scheduler
State; all other reads at that point follow Runtime admission. Existing
snapshots read these exact counters, reset at the original singleton boot.
The same owner/IRQ/lock/handoff barriers remain. Existing KERNELCOOP now has
equal and urgent competitors and observed intervals. Full evidence and limits:
Core/KernelCooperation08514.txt/.json. Foreign callbacks and hardware waits
retain their own contracts; no general kernel preemption or hard realtime.

ACPI work queues (0.81.16)
-------------------------

ACPIPLAT AML and Notify workers use resident binary semaphore events and
recheck their queue predicate. Empty queues no longer wake every 2 ms. Stop
closes enqueue admission, wakes and drains workers, and joins all callback
producers before freeing events. Start failure releases partial event state.
The SCI handler retains the 10-ms polling transport because DriverPlatformApi
has no SCI IRQ registration; an uninstalled handler incurs no periodic wake.
EC GPE callbacks wake the platform task. Only missing GPE or outstanding query
work needs 10-ms polling; idle GPE-capable controllers and lid safety use up to
1 second. Firmware event behavior on physical machines remains unmeasured.

Audio stream/output separation (0.81.17)
--------------------------------------

The common PCM core reserves writers/closers per stream and readers per mix
quantum. Conversion and mixing release the global stream mutex. A separate
resident semaphore output permit with task unwind binding serializes callback
lifetime and permits backend waits without holding stream metadata. Busy
retains source PCM. Backend shutdown first closes its callback admission and
retains all referenced storage on failed finalization. See Audio/README.txt.

  MADT-Speicherung und per-CPU Tabellen. Keine oeffentliche Threadaffinitaets-,

Windows-/Linux-Vergleich anhand offizieller Dokumentation, gelesen 18.10.2026:
- Windows dokumentiert prioritaetsgesteuerte Praeemption/Round-Robin,
  dynamische Priority-Boosts, Affinitaet/Ideal Processor, SMT-/Core-/Package-
  Beziehungen, NUMA und heterogene QoS-Platzierung sowie Processor Groups
  fuer mehr als 64 logische Prozessoren. R4OS hat den Grundmechanismus,
  aber nicht diese umfassenden Platzierungs- und Steuerungsmoeglichkeiten.
- Linux besitzt per-CPU Runqueues und periodischen topologischen Ausgleich
  ueber SMT-/SMP-/NUMA-Domaenen. EEVDF bewertet virtuelle Laufzeit und
  Fairness/Deadlines; Kapazitaetsbewusstsein, Affinitaet und CPU-Hotplug sind
  vorhanden. Nicht jede Architektur/Kernelkonfiguration nutzt alle Optionen.
- R4OS verwendet vier interne Rollen mit begrenzten Budgets, Rangspende und
  periodischer FIFO-Auswahl; daraus folgt keine EEVDF-, universelle
  Echtzeit- oder gleichartige Skalierungsgarantie. Der Windows-Vergleich
  beruht auf dokumentiertem Verhalten, nicht auf Einsicht in Windows-Quellcode.

Priorisierte Folgerung: zuerst den Einzel-Ready-Ausgleich und eine echte
Core-/SMT-/Package-Topologie beim Kernelbesitzer pruefen/verbessern. Weitere
Module und Worker nur nach ihrer eigenen Besitzerpruefung parallel freigeben.
Danach Hybrid-/NUMA-Politik, oeffentliche Hinweise und groessere CPU-Kapazitaet
nach Zielhardwarebedarf planen. Das vertrauenswuerdige Single-User-Modell
begruendet keine zusaetzliche Benutzer-, Rechte- oder Sandboxanforderung.
