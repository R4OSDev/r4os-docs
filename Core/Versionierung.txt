R4OS versioning
================

R4OS uses separate versions for separate owners:

- The release version is `RELEASE_VERSION` in
  `Repositories/Distribution/Injection/R4OS/CONFIG/VERSION.R4S`.
- The kernel artifact version is in `Repositories/Kernel/VERSION.R4S` and is
  embedded in `r4os.elf`.
- The six built-in Platform API implementations belong to that Kernel
  artifact. Their names, group IDs, Query revision and table layouts belong
  to the central Contract; they have no separate module version.
- Every R4M0 module version is the `VERSION` in its `module.R4MF` and is
  embedded in the built artifact.
- Runtime-R4L API major/revision values belong to the library-local contract
  and are independent of the module and release versions.
- R4U packages have their own package version and target release.

A release bump does not require an unchanged kernel, module or Runtime-R4L to
pretend it has a new version. Artifact versions change only when that artifact
changes. Compatibility is decided by explicit ABI versions, table sizes,
revisions and requirements, never by comparing the release string alone.
