R4OS filesystems and storage
============================

Layers
------

- R4D storage drivers register block devices.
- The block core owns stable device slots, request queues, workers and
  completions.
- The page cache owns cached sectors/pages, dirty state and writeback.
- The VFS dispatches mounted filesystems.
- NTFS is the normal system-volume format. FAT32 remains supported for
  additional media and compatibility.
- R4SYS exposes drives, directories, files, streams and atomic update
  operations to programs.

Block devices use stable tombstone slots. Unregister first stops new
admission and fails while mounts, operation pins, callbacks, queue entries,
locks or waiters still refer to the device. A successful unregister leaves no
live callback into the old driver.

Filesystem mutations are serialized by the owning volume rules. Long loops
cooperate with the scheduler; page-cache writeback does not replace explicit
durability points. Flush, atomic replacement and shutdown propagate backend
errors instead of reporting false success.

System paths are case-insensitive. Mixed case is preserved below
`C:\R4OS\Media\`; the remaining system tree normally uses uppercase names.
Applications use SDK file/path facades and do not call a filesystem backend
directly.
