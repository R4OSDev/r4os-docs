App-Projektstruktur 0.51.18
===========================

Ziel
----

0.51.18 trennt die erste Welle von R4X-Anwendungen praktisch vom Kernel- und
Root-Build. Jede migrierte App besitzt einen eigenen Build-Einstieg und kann
als einzelnes SDK-Projekt gebaut werden. `Code/build.zig` bleibt in dieser
Phase ein Dev-Aggregate-Build fuer das Standardimage, aber nicht mehr die
einzige Buildwahrheit der App.


Standardstruktur
----------------

Ein migriertes App-Projekt enthaelt:

    build.zig
    build.zig.zon
    src/
    module.R4MF
    README.txt

`build.zig` nutzt nicht den Root-Build, sondern laedt `r4os_sdk` als Paket:

    const sdk_build = b.lazyImport(@This(), "r4os_sdk") orelse return;
    const sdk_dep = b.dependencyFromBuildZig(sdk_build, .{});
    const sdk = sdk_build.sdk(b, sdk_dep, .{});

`build.zig.zon` bindet das SDK im Repository mit:

    .r4os_sdk = .{
        .path = "../../SDK",
    },

Dadurch ist der Projektbuild von `Code/build.zig` getrennt. Fuer externe IDEs
oder kopierte Projekte kann der SDK-Pfad spaeter im Projekt oder durch
R4CodePad angepasst werden.


Manifest
--------

`module.R4MF` beschreibt das gebaute Artefakt:

    R4OS_MODULE_MANIFEST=1
    KIND=R4X
    NAME=HELP
    SOURCE_PROJECT=Code\Software\Help
    ARTIFACT=Code\Software\Help\zig-out\HELP.R4X
    TARGET=/R4OS/SOFTWARE/TERMINAL/HELP.R4X
    BUILD_PROFILE=R4X_Zig_R4XStart_Console
    EXPORT=R4XStart:help_main:1
    CONTRACT=R4M0:1
    CONTRACT=R4XStart:1

Das Manifest zeigt auf das lokale App-Artefakt. Der Standardimage-Build nutzt
aktuell nur HELP.R4X direkt ueber dieses Manifest; die anderen migrierten Apps
werden noch vom Dev-Aggregate-Build ins Image gebracht. Der naechste Schritt
ist, weitere App-Manifeste in den Image-Sammelpfad zu uebernehmen.


Migrierte Apps
--------------

Erste einfache Anwendungen:
- Example -> EXAMPLE.R4X
- Beep -> BEEP.R4X
- BootInfo -> BOOTINFO.R4X
- Help -> HELP.R4X
- SysInfo -> SYSINFO.R4X
- MemView -> MEMVIEW.R4X

Konfigurations- und Systemtools:
- AppDefaults -> APPDEF.R4X
- RegistryTool -> REG.R4X
- RegEdit -> REGEDIT.R4X
- TimeSettings -> TIMESET.R4X
- DeviceManager -> DEVMGR.R4X
- Services -> SERVICES.R4X
- ServiceManager -> SERVMAN.R4X
- LogCenter -> LOGCENTER.R4X

R4Config ist kein produktives Quellprojekt mehr. Es wurde vor 0.51.X aus dem
produktiven Build/Image entfernt und wird deshalb nicht als App-Projekt
reaktiviert.


Abnahme
-------

Projektbuilds:

    powershell -NoProfile -ExecutionPolicy Bypass -File Tests\Gate\Run-AppProjectBuilds05118.ps1

Statischer Strukturcheck:

    DevTools\Zig\zig.exe run Tests\Gate\CheckAppProjectStructure05118.zig

Standard-Smoke:

    DevTools\Scripts\Build.bat -test
