Klickifax browser architecture
==============================

Klickifax is the R4OS browser application. Browser state is entirely
userland-owned:

- reusable HTML, CSS, layout, navigation, form, JavaScript and web-security
  helpers live in `Repositories/SDK/r4os/`;
- R4HTML, R4CSS, R4JS, R4HTTP and R4TLS are independent protocol modules;
- R4IMG and R4FONT are independent Runtime-R4Ls;
- Klickifax owns document generations, UI, caches and resource lifetimes;
- R4DRAW receives only completed drawing or raster data.

HTML reference search since 0.78.39
----------------------------------

The SDK HTML parser applies its existing 32-byte candidate limit before
searching for a semicolon. The inclusive boundary still accepts a semicolon
32 bytes after '&'. Missing, overlong or invalid references preserve literal
input and advance at least one byte; valid named and numeric references keep
their existing output. Source and document-string limits are unchanged.

An ampersand-only source therefore scans at most 32 following bytes per
input byte. A temporary scalar search observer attached to the same bounded
candidate records 130,544 inspected bytes for 4,096 input bytes and 261,616
for 8,192, with byte-identical literal output. These are search-work counts,
not a browser timing or FPS measurement; no observer remains in product code.
Three focused parser cases and two existing Klickifax inline-SVG cases cover
reference decoding, exact/overlong boundaries and downstream text use.

The parser is compiled into R4HTML, R4CSS, R4JS, Klickifax and KlickifaxLive;
all five artifact versions follow the rebuilt parser. The short installed
R4HTML probe uses its existing selftest and real render-text dispatch for
reference boundaries and a 4-KB literal ampersand sequence in local SMP4 QEMU.

Navigation replaces the document generation. Timers, listeners, requests,
promises and resources retain that generation so late completion cannot
mutate a newer page. Parser, VM, DOM, layout, image and cache limits fail
visibly rather than becoming unbounded allocations.

Validated JavaScript bytecode is bound to an explicit non-zero generation.
Normal, generator, and async entries compare that generation instead of
rehashing the complete program; a full fingerprint scan remains an explicit
diagnostic for trusted tooling. A script-free document keeps only the compact
WebRuntime base. Its JavaScript realm is allocated on first script or module
use and released as one lifecycle unit on abort, replacement, or shutdown.

RegExp quantifier layers are evaluated without consuming the 64-state pool
for every repetition, and ordinary linear atoms do not consume group or
backtracking depth. A search whose omitted alternatives could change a miss
fails explicitly with `RangeError`. Repeated DOM mutations share one pending
`dom_changed` action until the host consumes it; ordered navigation, history,
and form actions remain separate queue entries.

The supported HTML/CSS/JavaScript/Web API surface is intentionally limited.
The detailed, manually maintained status is
`Docs/Inventory/Browser.json`; unsupported functions must not be advertised
as complete. Offline fixtures provide deterministic coverage, while changing
public websites are useful manual observations rather than build gates.
