R4OS concurrency and responsiveness
===================================

The scheduler is preemptive. Wait queues, completions and dedicated workers
move blocking storage, filesystem, service and driver work out of IRQ and
reactor hot paths. Synchronous public calls may wait for completion but must
not secretly execute a second inline runtime path.

Rules
-----

- IRQ handlers perform bounded work and defer longer operations.
- A lock is not held across I/O, yield, wait or application callback.
- Wake producers publish state before signalling the matching wait queue.
- Completion at a timeout boundary wins when it can be proven.
- Desktop and drawing objects are owner-thread-only unless the API explicitly
  states otherwise.
- Service reactors process only short nonblocking requests; session work uses
  bounded workers or explicit asynchronous completion.

Module tasks may use SIMD. The scheduler saves a CPUID/XCR0-sized FPU state
for SIMD-capable tasks. The standard module target assumes AVX2; the kernel
is built without SIMD and remains ReleaseSafe.

SMP ownership foundation
------------------------

The x86_64 SMP foundation admits at most 32 ACPI processors. The BSP starts
each AP sequentially through a private low-memory INIT/SIPI trampoline and a
bounded wait. An AP becomes schedulable only after its CPU-local GDT, TSS,
GS base, FPU state, IDT, LAPIC and scheduler idle state are complete. Missing,
duplicate, disabled or failed APs stay outside the schedulable mask and never
prevent the BSP from continuing; one CPU is a permanent supported mode.

CPU-local state is one cache-line-sized `CpuLocal` record addressed through
GS. It owns the CPU index and APIC ID, lifecycle state, scheduler readiness,
legacy-critical depth and productive-work state. Current/idle task, Ready
queue and reschedule request are also per CPU. Initial placement chooses the
least-loaded online CPU, but a suspended stack stays bound to that CPU; this
foundation does not migrate live continuations.

Every AP qualifies its TSC against the shared HPET epoch before becoming
schedulable. Bounded per-CPU corrections feed one common nanosecond
clocksource, and a global monotonic clamp orders concurrent reads. Failed
correlation never discards an otherwise healthy AP: all CPUs switch to the
common HPET fallback. Logical ticks derive from this clocksource, while LAPIC
and HPET continue to own interrupt delivery and idle one-shots.

The ownership matrix is deliberately conservative:

- Per CPU: GDT/TSS/fault stacks, FPU register initialization, LAPIC timer,
  current and idle task, Ready queue, reschedule state and IRQ-dispatch depth.
- Explicit owner locks: virtual-range metadata, active page-table mutations,
  and the shared PMM/MemoryBlock physical metadata. Their fixed nesting order
  is VM (10), page tables (20), physical memory (30). A lower rank may never
  be acquired while a higher rank is held.
- Legacy cross-CPU serialized: Task identity, timed waits, deferred reap,
  heap metadata, boot log, IRQ registration/statistics and remaining owners
  that historically used disabled interrupts as their boundary.
- BSP-only until separately audited: pageable-VM I/O/reclaim, foreground and
  shell/console programs, services, GUI owners, R4D callbacks and ordinary
  legacy kernel workers.
- Parallel-enabled: explicitly marked CPU-only kernel work and the internal
  LoaderDiag `LSTRX.R4X` background fixture. Child threads inherit the exact
  audited owner class.

The transitional cross-CPU owner boundary is reentrant and uses
acquire/release publication. It is a no-sleep boundary: no I/O, wait, yield or
callback may occur while nested inside it. A context switch releases its
outer token only after the outgoing RSP is durable, and a remotely woken task
is queued only after its old CPU has physically switched out. This closes the
lost-wake, duplicate-stack and premature-reap windows without inventing a
public lock or affinity contract.

Every remaining `saveAndDisableFor` call belongs to one of eleven explicit
source classes; the default unclassified entrypoint has no caller. The source
inventory is:

- interrupt: `idt.zig`, `irq_router.zig`, `timer.zig`
- scheduler: `scheduler.zig`
- synchronization: `sync.zig`
- task: `task.zig`
- logging: `bootlog.zig`
- driver: `com.zig`, `usb_boot_wait.zig`, `driver_work.zig`
- memory: `heap.zig`
- storage: `storage/block.zig`
- network: `net/core.zig`, `net/serial_link.zig`
- program: `program/r4sys.zig`, `program/r4x.zig`
- test: `task_registry_selftest.zig`

Telemetry counts acquisitions, nesting, CPU collisions, total/maximum wait
spins and hold cycles without logging recursively from the lock path. Owner
locks additionally count order violations. Waiting task-context callers
briefly re-enable their original interrupt state between failed legacy-lock
attempts so the higher-priority TLB IPI remains serviceable.

Cross-CPU TLB coherence
-----------------------

R4OS currently uses one shared active kernel address space. Removing a PTE,
clearing hardware-dirty state or changing cache attributes therefore
publishes one generation and address/page-count request, sends vector F2 to
every other online CPU, and waits for a per-CPU acknowledgement of that exact
generation. Small ranges use `invlpg`; ranges of 64 pages or more reload CR3.
CPUs which become offline after the snapshot are excluded explicitly.

An invalidation has a bounded wait. On a missing acknowledgement the paging
owner restores the old PTE values and performs a recovery invalidation; the
caller receives failure and must not release or reuse the physical frame.
VM uncommit holds locks in VM -> page-table -> physical order and frees PMM
state only after a successful acknowledgement set. The short SMP4 acceptance
loads the old translation on all four CPUs, remaps to a distinct frame,
checks the new value everywhere, then drops one acknowledgement deliberately
and proves that unmap fails while the frame and mapping remain owned.

AP task switches currently occur at explicit cooperative scheduler points;
interrupt-frame preemption remains on the BSP. Each AP still owns a periodic
LAPIC accounting timer and receives reschedule IPIs. PCI INTx and single-
message MSI registrations choose internal online targets after AP activation.
No public CPU-affinity, priority or multi-vector ABI is exposed. Shutdown and
reboot remove APs from scheduling and stop them with a bounded IPI handshake.

New kernel threads enter their common trampoline through a synthetic context
switch rather than a hardware `call`. Its six saved-register words and one
reserved top word preserve the SysV x86_64 entry rule (RSP modulo 16 equals
8), so a worker may safely call SIMD-capable modules. A build-time layout test
keeps this stack contract synchronized with the assembly restore frame.

Scheduler work sets
-------------------

The stable Task registry owns identity and inventory only. Three intrusive
projections derive from it under the IRQ-disabled state-transition boundary:
the Ready FIFO, a stable ordered finite-deadline queue, and deferred-reap
candidates. Runnable selection and starvation diagnostics visit Ready tasks;
timeout dispatch starts at the deadline head and stops at the first future
wait. Equal deadlines retain enrollment order. One timer IRQ wakes at most 64
due tasks, leaving an ordered and diagnosed backlog for the next delivery. A
reaper pass visits only the candidates present at its start. Blocked unrelated
tasks do not increase these hot paths.

Active execution retains the periodic scheduler source needed for preemption.
When the current task is truly idle, HPET or the calibrated LAPIC is switched
to a one-shot for the queue head; an empty deadline queue disarms it. An
external wake cancels the pending shot and reevaluates the head. Long deadlines
use bounded hardware checkpoints. PIT systems remain periodic, while logical
ticks, watchdog budgets and runtime accounting continue on the same epoch and
do not count IRQ deliveries as elapsed time.

Kernel owners assign one of four internal scheduler roles: input, short
completion, interactive, or batch. No R4X or module API exposes role, priority,
or real-time selection. In particular, application and service program threads
remain interactive; only concrete short service-completion and selected kernel
workers receive a completion role. Priority remains a compact diagnostic lane
derived from the role.

Input activations receive 2 run ticks and 4 dispatches of rank-0 budget; short
completions receive 4 and 4 at rank 1. Consuming either bound demotes that
activation to interactive rank 2 until it blocks and is woken again. Batch is
rank 3. Selection takes the first task of the best rank from the Ready FIFO,
while every eighth non-urgent selection takes the raw FIFO head to preserve
cross-role NORMAL/LOW progress. A contended mutex may donate the waiter's rank
to its owner for at most 4 ticks and 4 dispatches; donation is removed on the
final unlock and cannot create an unbounded high lane.

A directed single wake chooses the best enrolled wake role and remains FIFO
inside one rank. Wake-all, cancellation, kill, and retry drains stay strict
FIFO. The producer publishes Ready state and a reschedule request while still
inside its critical section, but generic WaitQueue code never switches there.
IRQ work consumes the request only after all handlers and EOI. Synchronous
service and completion producers may use an explicit safe return point only
after their owner publication and locks are complete; enabled interrupts, zero
preemption depth, zero held locks, and no semaphore handoff are required. Until
then the request remains pending.
