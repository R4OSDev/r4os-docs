Klickifax browser architecture
==============================

Klickifax is the R4OS browser application. Browser state is entirely
userland-owned:

- reusable HTML, CSS, layout, navigation, form, JavaScript and web-security
  helpers live in `Repositories/SDK/r4os/`;
- R4HTML, R4CSS, R4JS, R4HTTP and R4TLS are independent protocol modules;
- R4IMG and R4FONT are independent Runtime-R4Ls;
- Klickifax owns document generations, UI, caches and resource lifetimes;
- R4DRAW receives only completed drawing or raster data.

HTML reference search since 0.78.39
----------------------------------

The SDK HTML parser applies its existing 32-byte candidate limit before
searching for a semicolon. The inclusive boundary still accepts a semicolon
32 bytes after '&'. Missing, overlong or invalid references preserve literal
input and advance at least one byte; valid named and numeric references keep
their existing output. Source and document-string limits are unchanged.

An ampersand-only source therefore scans at most 32 following bytes per
input byte. A temporary scalar search observer attached to the same bounded
candidate records 130,544 inspected bytes for 4,096 input bytes and 261,616
for 8,192, with byte-identical literal output. These are search-work counts,
not a browser timing or FPS measurement; no observer remains in product code.
Three focused parser cases and two existing Klickifax inline-SVG cases cover
reference decoding, exact/overlong boundaries and downstream text use.

The parser is compiled into R4HTML, R4CSS, R4JS, Klickifax and KlickifaxLive;
all five artifact versions follow the rebuilt parser. The short installed
R4HTML probe uses its existing selftest and real render-text dispatch for
reference boundaries and a 4-KB literal ampersand sequence in local SMP4 QEMU.

CSS declaration and sibling reuse since 0.78.40
---------------------------------------------

Comma-separated selector rules share one parsed declaration range. Rule
specificity, source order, layers and within-block declaration order still
select the cascade winner. A group of 900 selectors and five declarations
uses five declaration entries. Actual rule/declaration exhaustion rolls back
the appended source, base URL and all partially created rules as before.

Layout owns bounded SiblingIndex scratch and rebuilds it at the beginning
of each immutable DOM/style pass. Element positions in both directions,
same-tag positions and neighboring elements are reused throughout matching,
including nested functional selectors, pseudo elements and flex measurement.
The pass ends on return or error; the next reflow observes same-size DOM
moves, detach/attach/replace and new stylesheet rules. There is no mutation
through const Document pointers and no persistent computed-style cache.
Parent/tag grouping uses allocation-free heap sort with a sibling-position
tie-break; its work is bounded by O(N log N), independently of tag names.
Scratch belongs to Layout rather than a document-sized stack temporary.

A temporary observer on the actual implementation counts 131,328 sibling
links for uncached nth-child matching on 512 elements versus 513 links to
prepare the index; at 1,024 elements these counts are 524,800 and 1,025.
Indexed matching adds no sibling-link scans in these cases. Type grouping
performs 7,980 and 18,085 comparisons respectively. These are work counts,
not browser timing or FPS measurements. General sibling and descendant
combinators may still examine multiple candidate elements. Standalone
matchesSelector calls retain their correct uncached path; DOM query-list
matching is outside this layout optimization. The Map/Set work in 0.78.42
concerns JavaScript language collections rather than DOM query lists.

Flex measurement and explicit layout diagnostics since 0.78.41
-------------------------------------------------------------

Layout retains two exact measurement constraint variants per DOM node during
one reflow. Natural and forced widths/heights plus recursion depth distinguish
results; each DOM node follows one CSS inheritance chain in that immutable
document, stylesheet, interaction, image and font-provider pass. Moving the
origin translates the measured height. The first constraint remains available
and a third replaces the second; storage is bounded and allocation-free.
All entries are invalidated at the next reflow, including unchanged document
addresses/node counts with modified styles, text, viewport or font metrics.
Providers must keep their metrics stable within that synchronous pass.

Only measurement reuses scalar heights, including nested measured blocks.
Final publication always emits actual operations, clipping, text and extents
at the final origin. Failed measurements restore counters and pass state;
real output capacity limits still apply. No render-list copies or persistent
computed-style results are retained for this optimization.

The eight-level single-child flex fixture falls from 9,842 full block runs
(including its body wrapper) to 25. Seven bounded baseline comparisons retain
all render-operation fields, text, extents and structural hashes across depth,
width, relative padding, font metrics, fixed-height growth and narrow alignment
changes. These are implementation work counts rather than elapsed-time claims.
Additional owner cases check mutable text without changing node count and
recovery from a RenderLimit failure.

LayoutStats and stats() now return only constant-time counters. Explicit
Layout.diagnosticStats() returns LayoutDiagnosticStats with the unchanged
structural hash; structuralHash() remains directly available. Reflows do not
compute it implicitly. R4CSS layout summaries and selftests request the hash
explicitly and preserve their protocol output. Klickifax and KlickifaxLive
use ordinary reflow without paying for an unused diagnostic scan.

JavaScript collection and accessor ownership since 0.78.42
---------------------------------------------------------

Map, Set, WeakMap and WeakSet lazily allocate hash buckets and entry metadata.
Values and presence bits remain in the existing cell item storage for strong
and weak GC tracing. Lookup follows only a key's live bucket chain; size is
constant-time. Deletion unlinks the entry and reuses its physical slot, while
a separate linked order preserves insertion order. Updating a key keeps its
position; deleting and inserting it gives it a new position. clear() resets
the live storage without resetting the monotonic insertion serial.

Active iterators and forEach use an entry position plus insertion serial.
The common path follows the next live entry. Deleting/reusing the last entry
or clearing the collection recovers the cursor from the current live order.
Exhausted iterators remain exhausted. SameValueZero hashing canonicalizes
signed zero and NaN and respects string/BigInt values and object identity.
Weak GC deletion updates the same index and free list. Metadata contains no
additional JavaScript roots and is released with its owning collection.

Collection limits apply to the actual live count. A full Map reports a
catchable RangeError, and deleting an entry makes room for another key.
Growth allocation failures preserve existing entries, values and order;
successfully reserved capacity may remain available for a retry. Allocated
capacity can retain a past peak, but repeated small-live-count churn reuses
storage instead of growing with all past insertions. In a 512-cycle bounded
fixture, Map search steps fell from 395,008 to 1,046 and the physical item
high-water mark from 1,026 to 4. These are work counts, not timing claims.

Accessors retain property markers for enumeration and use per-owner linked
indices for lookup, integrity operations and GC marking. Owner collection
releases its chain before a cell ID can be reused. Deleted or converted
accessors return to a pool free list; pool relocation keeps indices valid.
Normal properties do not scan other owners or historical pool capacity.
The bounded fixture performs zero accessor comparisons for 64 ordinary
property reads after collecting 512 discarded accessor owners, versus
65,536 comparisons before this change. Pool capacity remains reusable.

Bounded native JavaScript sorting since 0.78.43
----------------------------------------------

Array and TypedArray sort()/toSorted() use a stable bottom-up merge of
original indices. Two u16 index arrays require at most 256 KB at the existing
65,536-element sorting limit. An ordered-input check retains linear work for
already sorted inputs. Otherwise comparison work is O(n log n), with stable
left-first ties, including a comparator result of NaN. Array sort() gathers
present values and writes undefined before holes; toSorted() reads holes as
undefined. Undefined values never reach an Array comparator.

TypedArray sorting captures exact element bytes in at most 512 KB instead
of a full JavaScript Value array. Comparators cannot change this snapshot
by modifying, resizing or detaching the receiver. Final writes recheck the
view: detached/out-of-bounds indices are ignored, immutable storage fails.
Default comparison preserves numeric ordering, signed zero, NaN placement,
NaN payload stability and exact signed/unsigned 64-bit BigInt ordering.
Only custom BigInt comparisons materialize the two compared values, with
temporary roots across callbacks. A missing ordinary BigInt-versus-BigInt
relational comparison branch found by that case was corrected as well.

Gathering, index initialization, order checks, merging, permutation and final
writes call the existing checkpoint. Native work therefore consumes the
step budget and observes the configured stop interval; it is no longer an
uninterruptible insertion-sort loop. Scratch is released on every exit and
cycle values remain rooted across collection. String conversion retains
references until both conversions finish before resolving arena pointers.

The bounded 512-element reverse fixture drops from 130,816 comparisons to
2,305 for both paths; sorted input remains at 511 comparisons. Default typed
sorting creates no temporary JavaScript cells. A single targeted StepLimit
case interrupts actual comparisons before receiver writeback and verifies
that roots unwind and the same runtime subsequently evaluates 6*7 as 42.
These are work counts and focused behavior checks, not elapsed-time claims.

Web object ownership within a document since 0.78.44
---------------------------------------------------

The nine stream internal-slot registries use WeakMap. Reader, writer,
controller, BYOB request and transform state follow their reachable owners
through the runtime's ephemeron fixed point. Queued promise work retains its
required state; completed objects retain their promised state while still
referenced. The active pipeThrough operation set stays strong until completion.
Document replacement remains a final boundary, not the only reclamation point.

ExternalRootMarker now supports conditional marking in that same fixed point
and a sweep callback before cell IDs become reusable. These callbacks only
inspect, mark or clear metadata: no allocation, JavaScript call or nested GC.
WebRuntime strongly retains requests while queued, in flight or processing a
terminal response. A processing flag also prevents a callback from reusing
the currently completing request slot. Terminal request references are
cleared during collection; their response metadata remains available.

XHR registry entries and their event listeners follow the XHR object instead
of rooting every completed request. Registered MutationObservers remain
anchored by their observation; otherwise state follows the reachable owner.
Queued mutation deliveries carry the observer object, not a reusable slot
number, and keep it alive even after disconnect clears the queued flag.
Construction roots and reserves owners across fallible setup, with rollback;
receiver lookup validates current object identity before using a slot.
Full XHR, observer and signal-link registries attempt one collection before
reporting a limit on the actual retained owners or pending work.

AbortSignal hidden state caches only GC flags for completion and actual
listener interest. A retained target keeps its sources; a reachable source
keeps an interested dependent target. Unrooted cycles do not bootstrap their
own roots. This preserves listener delivery required by DOM section 3.2.1:
https://dom.spec.whatwg.org/#abortsignal-garbage-collection
GC never invokes property getters to determine this interest. Pending abort
delivery explicitly roots its targets; relation cleanup also runs on errors.
Expiring deadlines root their signal before clearing the deadline and creating
the timeout error, covering collection before abort delivery starts.

Three focused owner cases supplement existing stream/observer/signal cases.
Sixteen stream cycles finish 68 operations and return from a pending peak
of 1,116 cells to the warmed baseline of 945. Sixty-four register cycles
retain only one deliberately kept XHR, one observer reached through WeakMap
and two signal links; after releasing them all three counts are zero.
Collection inside response, observer and signal callbacks preserves delivery,
a virtual timeout completes its unreferenced dependent, and a nested XHR uses
a different request slot. Disconnected pending observer
work drains without invoking the disconnected callback or reusing its owner.

Stream queue and byte transport since 0.78.45
-------------------------------------------

Readable chunks, pending reads and capacity waiters use a geometrically grown
ring. Consumption clears its slot and does not move remaining entries. Empty
slots are reused; clearing releases the backing array. The existing runtime
array capacity remains the live queue limit. In a bounded measurement, draining
512 queued chunks or pending reads previously moved 130,816 entries. The ring
moves 504 entries while growing and none while removing them; at 256 entries
the corresponding counts are 32,640 versus 248.

Byte enqueue, BYOB read and producer responses use the existing ArrayBuffer
transfer operation. It detaches the previous buffer and currently copies its
storage natively; this is not a zero-copy claim. Internal view descriptors
preserve the intrinsic typed-array/DataView kind, byte offset and element size.
Partial reads commit aligned elements and retain remaining bytes for the next
read. Producer views are invalidated on response; replacement buffers must
match the pending span. Pending BYOB close is completed by respond(0), whereas
reading an already closed stream returns a transferred empty view directly.
A queued body that cannot satisfy the requested minimum rejects the read.

BYOB copies use Uint8Array.set. Identical-element TypedArray.set uses native
blocks of at most 4096 bytes, handles whole-span overlap in the proper direction,
and revalidates both buffers after offset conversion. It preserves raw float
and BigInt bits without allocating an intermediate Value array. Other element
kinds and generic array-like inputs retain their conversion path. A 128 KB copy
previously failed at the 65,536-item Value-array limit; it now uses 32 blocks
and zero temporary Value cells. The existing budget/stop checks remain active.

tee shares one pending source read between branch pull requests. Normal branch
demand determines subsequent reads; one fast reader may still accumulate data
in the other branch, as required. Byte branches have independent buffers.
Both cancellations join their reasons and cancel the source once. Source errors
reach both branches even without a new pull. A byte branch ending with an
incomplete element errors without preventing the other branch from completing.
The focused tests include one pull without readers, concurrent demand, an
unused branch, cancellation, errors, buffer ownership and queue reclamation.
Reference: https://streams.spec.whatwg.org/#rs-tee

Navigation replaces the document generation. Timers, listeners, requests,
promises and resources retain that generation so late completion cannot
mutate a newer page. Parser, VM, DOM, layout, image and cache limits fail
visibly rather than becoming unbounded allocations.

Validated JavaScript bytecode is bound to an explicit non-zero generation.
Normal, generator, and async entries compare that generation instead of
rehashing the complete program; a full fingerprint scan remains an explicit
diagnostic for trusted tooling. A script-free document keeps only the compact
WebRuntime base. Its JavaScript realm is allocated on first script or module
use and released as one lifecycle unit on abort, replacement, or shutdown.

RegExp quantifier layers are evaluated without consuming the 64-state pool
for every repetition, and ordinary linear atoms do not consume group or
backtracking depth. A search whose omitted alternatives could change a miss
fails explicitly with `RangeError`. Repeated DOM mutations share one pending
`dom_changed` action until the host consumes it; ordered navigation, history,
and form actions remain separate queue entries.

The supported HTML/CSS/JavaScript/Web API surface is intentionally limited.
The detailed, manually maintained status is
`Docs/Inventory/Browser.json`; unsupported functions must not be advertised
as complete. Offline fixtures provide deterministic coverage, while changing
public websites are useful manual observations rather than build gates.
