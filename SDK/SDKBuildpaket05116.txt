SDK-Buildpaket 0.51.16
======================

Ziel
----

0.51.16 macht das SDK zum eigenstaendigen Build-Paket fuer externe
R4OS-Module. Ein App-Projekt soll nicht mehr annehmen, dass es unter
`Code/` liegt oder dass es SDK-Dateien in seinen eigenen Quellbaum kopieren
muss.

Die saubere Kopplung besteht aus zwei Teilen:

1. Das App-Projekt bindet das SDK als Zig-Paket `r4os_sdk` ueber
   `build.zig.zon`.
2. Das App-Projekt uebergibt nur eigene Quellen mit `b.path(...)`.
   SDK-interne Pfade werden vom SDK-Hostprofil aufgeloest.


Paketbindung
------------

`Code/System/SDK/build.zig.zon` beschreibt das SDK als Paket:

```
.{
    .name = .r4os_sdk,
    .version = "0.51.16",
    ...
}
```

Ein externes Projekt kann das SDK lokal so binden:

```
.dependencies = .{
    .r4os_sdk = .{
        .path = "../Pfad/zum/Code/System/SDK",
    },
},
```

Im externen `build.zig` wird nicht per absolutem `@import` auf eine Datei im
SDK gezeigt. Stattdessen wird die Build-Datei des Pakets ueber Zig selbst
geladen:

```
const sdk_build = b.lazyImport(@This(), "r4os_sdk") orelse return;
const sdk_dep = b.dependencyFromBuildZig(sdk_build, .{});
const sdk = sdk_build.sdk(b, sdk_dep, .{
    .r4x_builder_source = .{ .cwd_relative = "D:/.../Code/BuildTools/R4XBuilder/src/main.zig" },
});
```

Danach kennt `sdk` die SDK-internen Pfade:

- `r4os.zig`
- `r4os/linker/r4os_module.ld`
- `Shared/C/include`
- `Shared/C/src/r4xstart_startup.c`
- R4XBuilder-Quelle ueber Hostprofil oder Uebergangsparameter


Oeffentliches Build-Interface
-----------------------------

`Code/System/SDK/r4os/build.zig` stellt zwei Ebenen bereit:

- Low-Level-Helfer `addR4X`, `addR4D`, `addR4P`, `addR4LRaw` fuer den
  bestehenden internen Repo-Build.
- Einen neuen `Sdk`-Handle fuer externe Projekte. Dieser Handle besitzt ein
  `HostProfile` und bietet:
  - `sdk.addR4X`
  - `sdk.addR4XStart`
  - `sdk.addR4XStartC`
  - `sdk.addR4XService`
  - `sdk.addR4D`
  - `sdk.addR4P`
  - `sdk.addR4LRaw`

Der neue Handle zentralisiert:

- Zielarchitektur `x86_64`
- freestanding Target
- SIMD-/FPU-Verzicht bis R4OS Task-State dafuer sichert
- Linkprofil
- R4M0-Packaging
- R4XStart-Exports und Metadaten
- C-Header, C-Startup und C-Entry-Konvention
- R4D-/R4P-Exports und Standardimports


Hostprofile
-----------

Die physische Struktur ist vorbereitet:

```
Code/System/SDK/
  Shared/
  Hosts/
    Windows/
    Linux/
    R4OS/
```

`Shared` ist der gemeinsame SDK-Kern. `Hosts` enthaelt nur Host-spezifische
Huellen: Toolpfade, Runner, Paketierung und spaeter IDE-Integration.

Windows ist der erste produktive Host fuer R4CodePad und lokale Zig-Builds.
Linux und R4OS verwenden spaeter denselben SDK-Kern. Sie duerfen keine eigene
ABI-Schicht erfinden.


Uebergangsparameter
-------------------

Fuer 0.51.16 gibt es zwei klare Uebergangsparameter:

- `-Dr4os-sdk=...`
  SDK-Root, wenn ein Build nicht ueber `build.zig.zon`/Dependency-Pfad
  gebunden wird.

- `-Dr4os-r4xbuilder=...`
  Pfad zu `R4XBuilder/src/main.zig`, solange R4XBuilder noch nicht als
  exportierter Bestandteil eines SDK-Pakets ausgeliefert wird.

Diese Parameter sind Host-Konfiguration. Sie gehoeren nicht in die ABI, nicht
in `.R4CP`-Projekte und nicht in App-Quellcode.

Nachtrag 0.61.9: Der zweite Uebergang ist beendet. R4XBuilder liegt seit
0.61.9 unter `Code/System/SDK/Tools/R4XBuilder` und ist damit exportierter
Bestandteil des SDK-Pakets - genau die Bedingung, unter der dieser Bericht
`-Dr4os-r4xbuilder` als voruebergehend bezeichnet hat. Der oben gezeigte
absolute Pfad ist historisch; ein externes Projekt uebergibt heute nichts
mehr und bindet nur noch das SDK selbst. Der Parameter bleibt als
Host-Override bestehen, wird aber nicht mehr gebraucht. Bewacht wird das
von `Tests/Gate/Run-SdkSelfSufficiency.ps1`.


Externe Abnahme
---------------

`Tests/Gate/Run-SDKExternalBuild05116.ps1` erzeugt ein
temporaeres Projekt unter `Release/SDKExternalBuild05116` und baut ein
minimales R4X:

- Projekt liegt ausserhalb von `Code/`.
- SDK wird per `build.zig.zon` als `r4os_sdk` gebunden.
- App-Quelle wird zuerst aus `src/main.zig` gebaut.
- Dasselbe Projekt wird danach mit verschobener App-Quelle
  `moved/main.zig` gebaut.
- Das Ergebnis `EXT05116.R4X` wird mit R4XBuilder inspiziert.

Damit ist der wichtige Schnitt abgenommen: App-Quellort und SDK-Quellort sind
getrennt, aber der Build bleibt reproduzierbar.
