R4OS 0.21.X Modulabschluss
==========================

0.21.X hat das API- und Modulmodell von der alten Flat-Binary-Welt auf einen
gemeinsamen R4M0/R4L-Vertrag umgestellt.

Abschlussstand 0.21.11
----------------------

- R4L ist die sprachneutrale ABI-Schicht fuer R4OS-API-Gruppen.
- Die API-Gruppen liegen als echte R4L-Binaerartefakte vor:
  `R4SYS.R4L`, `R4DESK.R4L`, `R4DRAW.R4L`, `R4NET.R4L`, `R4AUDIO.R4L` und
  `R4DEV.R4L`.
- Diese API-R4L-Dateien werden ueber `C:\SYS\LIBS` geladen, importieren intern
  den privaten `KernelProvider:KernelPing:1` und exportieren `Query:1`.
- Normale R4X-, R4D- und R4P-Module importieren oeffentliche API-Gruppen wie
  `R4SYS:Query:1` oder `R4DEV:Query:1`, aber nicht direkt den KernelProvider.
- Die aktuelle Inventarliste aus Docs/Software.md besteht aus R4M0-
  Artefakten oder bewusst erwarteten Negativfaellen im neuen Resolverpfad.
- Der alte Flat-Binary-Vertrag `R4X0`/`R4D0`/`R4P0` ist kein Betriebsmodell
  mehr. OLDLEG-Proben pruefen im Bootlauf, dass er abgelehnt wird.

Abnahme
-------

Der finale Gate besteht aus:

    DevTools\Scripts\Build.bat -norun
    DevTools\Scripts\Build.bat -test
    DevTools\Scripts\Build.bat -testonly
    DevTools\Zig\zig.exe run Tests\Gate\CheckRoadmap021.zig
    DevTools\Zig\zig.exe run Tests\Gate\CheckR4XConsole021.zig
    DevTools\Zig\zig.exe run Tests\Gate\CheckR4XGui021.zig
    DevTools\Zig\zig.exe run Tests\Gate\CheckModuleMigration021.zig
    DevTools\Zig\zig.exe run Tests\Gate\CheckLegacyRemoval021.zig
    DevTools\Zig\zig.exe run Tests\Gate\CheckFinalModules021.zig

`CheckFinalModules021.zig` ist der Abschlusscheck fuer 0.21.11. Er prueft die
sechs API-R4L-Dateien binaer, die aktuelle Inventarzaehlung aus
Docs/Software.md, KernelProvider-Policy, Image-Liste, Bootlog-Diagnosen,
COMMAND.R4X `/LEGACY`, LOADERD, SERVMAN und BOOTINFO. Seit 0.45.3 erwartet
das Gate keinen Kernel-`MODULETEST` mehr; seit 0.45.4 prueft es, dass die
historischen 0.21-Loaderfixtures nicht mehr im Standardimage injiziert
werden.

Grenzen
-------

Die API-Gruppen sind nun als R4L-Binaerartefakte und ABI-Schicht sichtbar.
Ein Teil der fachlichen Funktionsumsetzung laeuft intern weiterhin ueber
Kernel-/Runtime-Bruecken. Das ist kein Legacy-Dateiformatvertrag mehr, sondern
die aktuelle Implementierung hinter der R4L/SDK-Oberflaeche.
