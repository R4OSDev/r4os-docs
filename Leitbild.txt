R4OS Leitbild
=============

R4OS ist ein single-user, fully trusted Betriebssystem.

Es gibt bewusst kein Sicherheits- oder Berechtigungsmodell:
- keine User/Groups
- keine File-Permissions
- keine Sandbox
- keine Capability-Checks
- keine Zugriffsbeschraenkungen auf Devices

Validierung bleibt trotzdem erlaubt, wenn sie technische Stabilitaet schuetzt
oder kaputte Parameter abfaengt. Das ist keine Security-Policy, sondern
Crash-Vermeidung.

R4OS soll DOS-artige Freiheit bieten: Programme und Services sollen viel
direkt tun duerfen. Intern darf das System trotzdem sauber modularisiert sein,
damit Kernel, Services, Shell, Dateisystem, Module und spaeter der
DOS-Emulator getrennt entwickelt werden koennen.

R4OS verwendet ein DOS-artiges Laufwerksmodell statt eines Unix-artigen
Root-Baums:
- C: ist das Systemvolume und traegt den R4OS-Baum.
- D: ist die Datenplatte.
- Die Bootpartition bekommt bewusst KEINEN Laufwerksbuchstaben: sie ist
  kein allgemeines Laufwerk und wird intern eingehaengt, damit /boot-Ziele
  trotzdem erreichbar bleiben.
- Weitere Laufwerke koennen fuer Disk, RAM, Module oder virtuelle Systeme
  hinzukommen; RAM-Laufwerke sind im Modell vorgesehen, werden beim Boot
  aber nicht mehr angelegt.

Ein wichtiges Langzeitziel ist Selbstveraenderbarkeit:
- R4OS soll eigene Systemdateien auf Disk ersetzen koennen.
- R4OS soll Kernel-Module zur Laufzeit laden koennen.
- R4OS soll langfristig im eigenen System Code bearbeiten, bauen und
  installieren koennen.

Das Systemdateisystem ist seit 0.60.9 NTFS 3.1, mit vollstaendigem Lese- und
Schreibpfad und Windows-chkdsk-kompatiblem Ergebnis. FAT32 bleibt unterstuetzt
und traegt die Bootpartition sowie die Datenplatte. Ueber beiden liegt eine
FS-neutrale VFS-Schicht; Programme sehen nur den R4SYS-Datei- und
Verzeichnisvertrag und nicht das darunterliegende Dateisystem.
