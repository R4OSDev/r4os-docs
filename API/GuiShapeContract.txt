GUI shape and frame contract
============================

Complex rounded rectangles, borders, shadows, gradients and similar UI
effects are described as bounded frame commands plus caller-owned payload
bytes. R4DRAW validates command kinds, dimensions, offsets, clipping and
payload ranges before accepting a frame.

A frame uses an explicit transaction:

1. begin a frame;
2. append one or more command/payload batches;
3. commit the complete frame or cancel it;
4. let the desktop read the immutable committed snapshot.

A failed append does not publish a partial frame. Commands never retain
pointers into an application buffer after the append call; required bytes are
copied into the frame transaction. The desktop rasterizes only the validated
snapshot and does not reinterpret application memory.

Numeric layouts, command kinds and limits are generated from the platform
Contract and are not duplicated here.
