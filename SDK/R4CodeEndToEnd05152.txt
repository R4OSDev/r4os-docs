R4CODE End-to-End 0.51.52
=========================

Ziel
----

0.51.52 schliesst den ersten R4CODE-Self-Hosting-Block ab.
R4OS kann im eigenen System die beiden ersten C-Projektvorlagen aus dem SDK
erzeugen, bearbeiten, bauen und starten:

- R4X C Terminal Hello
- R4X C Desktop OK

Der Pfad bleibt komplett innerhalb von R4OS:

- Templates: `C:\R4OS\SDK\Templates\R4OS\`
- IDE: `C:\SOFTWARE\R4CODE\R4CODE.R4X`
- Worker: `C:\SOFTWARE\R4CODE\R4BUILD.R4X`
- Packer: `C:\SOFTWARE\R4CODE\R4PACK.R4X`
- Compiler: `C:\R4OS\SDK\Toolchains\C\bin\R4CC.R4X`


Selftest
--------

`R4CODE.R4X /SELFTEST` erzeugt die Projekte aus den installierten
SDK-Templates. Danach schreibt der Test eine geaenderte `src\main.c`, damit
auch der Editor-/Source-Update-Fall abgedeckt ist.

Die R4CP-Erzeugung nutzt den SDK-Helfer `r4os.r4cp.renderProjectTemplate`.
Dieser Pfad ersetzt im R4CODE-Runtime-Pfad den generischen Token-Array-
Renderer, damit die interne IDE denselben spezialisierten und stabilen
Templatepfad nutzt wie der Selftest.

Console:

- Projekt: `C:\TEMP\R4CODE\HELLOC\HELLOC.R4CP`
- Quelle: `C:\TEMP\R4CODE\HELLOC\src\main.c`
- Artefakt: `C:\TEMP\R4CODE\HELLOC\out\HELLOC.R4X`
- Abnahme: Build ueber R4BUILD, R4CC-Console-Profil, R4PACK, Start als
  Console-R4X.

Desktop:

- Projekt: `C:\TEMP\R4CODE\HELLOGUI\HELLOGUI.R4CP`
- Quelle: `C:\TEMP\R4CODE\HELLOGUI\src\main.c`
- Artefakt: `C:\TEMP\R4CODE\HELLOGUI\out\HELLOGUI.R4X`
- Abnahme: Build ueber R4BUILD, R4CC-Desktop-OK-Profil, R4PACK,
  `r4x.class=gui`, Imports R4SYS/R4DESK/R4DRAW, Start als GUI-R4X,
  Close-Request ueber R4SYS.


No-Fallback-Regel
-----------------

Der produktive Pfad darf nicht auf Host-Werkzeuge ausweichen:

- kein R4CodePad
- kein Build.bat
- kein DevTools-Compiler
- kein Windows-/Linux-Compiler
- kein Host-R4XBuilder
- keine privaten R4CODE-Templates
- keine vorgebauten Beispielartefakte

Das statische Gate `CheckR4CodeEndToEnd05152.zig` prueft diese Regel fuer
R4CODE, R4BUILD, R4PACK, R4CC, SDK-Templates und Test-AUTOEXEC.
Es prueft ausserdem, dass R4CODE fuer Projektvorlagen den spezialisierten
R4CP-Renderer nutzt und nicht wieder auf den generischen Token-Array-Renderer
zurueckfaellt.


Grenze
------

Der automatische Standardtest laeuft headless. Er kann deshalb keinen echten
Mausklick auf den OK-Button ausfuehren. Stattdessen startet der Selftest das
Desktop-Artefakt, setzt einen `program_request_close` und raeumt danach
technisch auf. Der sichtbare OK-Klick bleibt ein manueller GUI-Sichttest mit
`DevTools/Scripts/Build.bat -gui`.
