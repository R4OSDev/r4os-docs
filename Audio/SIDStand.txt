SID in R4OS
============

SID support is split into independent components:

- `Repositories/Drivers/SID/` owns the loadable SID engine and its runtime
  state.
- `Repositories/Protocols/AudioSid/` owns the SID protocol role.
- `Repositories/Apps/R4Synth/` is the normal player and consumer.
- R4AUDIO exposes the public operations required by applications.

There is no productive second SID implementation in the kernel. The driver
owns register state, model selection, playback frames and cleanup. Protocol
parsing and application presentation remain outside the driver.

The current implementation targets the documented 6581/8580 behavior needed
by R4Synth. Hardware-faithful analog behavior is not promised; deterministic
software output and a clean component boundary take priority.

SID.R4D resolves model, register and mirrored-I/O operations through the
installed AudioSid.R4P using the append-only DriverApi v18 protocol bridge.
The kernel reapplies the configured SID model after protocol loading, so the
driver never needs an embedded substitute protocol.

Each successful play step produces one PCM block for the active audio
backend. If that backend reports backpressure, the block remains pending and
the caller retries the same frame. Hard backend or runtime failures are
returned unchanged. Stop, release and error cleanup share the same
idempotent pending-state reset.


Playback boundaries and cadence (0.78.74)
---------------------------------------
A host routine call supplies an emulated return address. Nested JSR/RTS and
balanced stack data continue until the outer return restores the caller's
stack and return target; BRK, unsupported instructions and exhausted budgets
remain failures.

Each public load replaces the entire title RAM and resets the runtime,
registers and fractional audio state, including after an invalid load.
Init must start inside the current image. Play may also start in RAM written
by that title, allowing relocated or decompressed code. Mapped I/O and absent
ROM are not executable entry points. The diagnostic loadProgram helper can
assemble multiple segments explicitly; sid_load_data never appends them.

PCM uses 48000 stereo s16le frames per second and carries integer division
remainders between intervals. The driver returns the exact byte count,
including silence; a short output buffer does not consume the interval.
The existing 3840-byte contract admits integer rates from 50 to 48000 Hz;
zero selects 50 Hz. Changing cadence starts a new remainder sequence.

R4Synth selects 50-Hz PAL VBI or 60-Hz NTSC/default CIA cadence from the
selected subtune's speed bit and clock flags. Legacy speed bits wrap after
32 subtunes; C64-compatible modern headers reuse bit 31. Its sleep accounting
uses the same cadence. A zero init address uses the effective load address.
Interrupt-driven PSID and RSID are reported as unsupported, rather than
claiming playback after only init. This remains a routine-driven renderer:
PAL oscillator/VIC timing, dynamic CIA timers and full ROM/IRQ execution
are outside this correction; NTSC cadence does not imply full NTSC emulation.

Format reference: https://hvsc.c64.org/download/C64Music/DOCUMENTS/SID_file_format.txt

Synth, protocol and other audio-driver review (0.88.13)
------------------------------------------------------
Bounded source review: MIDI/OPL3/SID/AudioFail drivers, AudioMidi/AudioOpl3/
AudioSid protocol dispatch, current native SDK/advanced operations, Kernel
synth integration, normal R4Synth callers and actual module image activation.
This is not a complete chip-faithfulness review, current SYNTHD guest run,
concurrent-process fault injection or new physical sound/latency acceptance.

0.88.52 owns SID-Stop interference with the common PCM output. sid_stop always
calls stop_active_pcm after the private synth Stop, without checking other
open PCM sources. That is a physical Stop on the shared active backend; it
can drain/restart unrelated playback. Other core final-close logic explicitly
considers other streams/synths. Preserve private SID halt/Pending semantics
while letting the common output owner decide when it really becomes idle.
This source call sequence is not a measured audible dropout or a proven cause
of historical SNES starvation.

0.88.53 owns exclusive synth-session lifetime. Core has only global SID/MIDI
acquired flags and active synth slot, with generic handle1. R4AUDIO synth
entries are direct; unlike PCM stream bindings they do not record the R4X
caller generation. Reaper action9 closes owned PCM streams, not these exclusive
synth sessions. The driver SID acquire/release adapters likewise know no R4X
owner. Normal R4Synth explicitly stops/releases/closes, but an aborted/faulted
process cannot be assumed to finish that code. The follow-up must test actual
two-client/fault/SMP behaviour and bind real resource lifetime, without adding
a permission/sandbox model or blocking all PCM behind synthesis work.

0.88.54 owns obsolete private no-op diagnostic scaffolding in SID/OPL3 engines.
k.puts/putDec/putHex/putc are empty; dumpStatus has no active caller. SID's
last_io_read/write address/value stores feed only that empty dump; private
protocolStatus has no active driver/app consumer. Generic R4DEV protocolStatus
in SYNTHD is a different real function. Only individually proved no-reader data
is removable. OPL3 last_mixed_channels, SID clock/RAM/write maps/phase/filter/
envelope state and genuine SynthEngineStatus counters have other meaning and
must remain. Compiler elimination may already remove private stores/empty calls;
no actual normal log stream or speedup follows from their source definitions.

Preservation findings: mapped SID writes already dispatch ResolveIo once and
call writeRegisterDecoded, avoiding a second protocol classification. Direct
public register writes retain their one required classification. Required
protocol binding is not an old-OS substitute; missing/failed roles remain real
errors. MIDI.R4D is explicitly a router without PCM renderer; choosing a
renderable MIDI synth does not treat that router as an audible renderer.
Synth rendering remains bounded; pending PCM is retried rather than rerunning
the same SID frame after backpressure. Original SID routine-return/step limits,
full title-load replacement including invalid loads, exact cadence/remainder/
PCM byte count and unsupported ROM/IRQ formats remain. No shortened synthesis,
phase reset on silence or simplified substitute audio was proposed.

The three protocol selftests are explicit dispatch operations, not automatic
per-sample checks; no Kernel caller of their self-test opcodes was found.
AudioFail is the deliberate negative AC97FAIL init fixture (return-38), marked
negative and IMAGE_SCOPE=none; ordinary image configs contain no such module.
Its existence does not create normal driver failure/probe overhead. Keep it for
loader/failure coverage. Building it does not execute its intentional init error.

All seven relevant unchanged owner builds/container inspections succeeded with
exit0: MIDI,OPL3,SID,AudioFail R4Ds and AudioMidi/AudioOpl3/AudioSid R4Ps. Output
went only to Temp and those completed modules were removed. No new test gate,
full system catalog or runtime selftest run is claimed. Earlier focused SDK
platform cases cover the common facade boundary only, not these real engines.
Sources/product artifacts remain unchanged; docs/status/release marker only,
no STANDARD/new image/hardware action from this analysis.
